Appendix B.3. AFW 360 transition: decisions

Decisions taken, hard cases to confirm at gate G0, and gaps in the standard

Published

September 21, 2026

1 How this sheet is used

Agents build the transition pipeline with the recommended coding of every open hard case (Section 3), marked DRAFT. Nothing built from a DRAFT coding is ACTIVE until the user says so.

At gate G0, which is asked at the start of the run and before anything is built, the user confirms or flips each open case (decision D10). The wave-1 integrator records the answers in the Status and User note lines of this sheet and in reports/GATE-G0.md. A flip is applied once, by package WP99, to the contract seeds (contract/label_triage.csv, codes.csv, legacy_overrides.csv), and contract/check_contract.R recomputes the expected counts. Every later package then builds the flipped coding from the start.

Related documents: plan, contract, package cards, standard, input findings.

2 Decisions taken

Table 1 lists the nine decisions the user made on 2026-09-21, overriding the triage report where the two differ. All are final; none needs confirmation at a gate. D10 to D12 were added on 2026-09-21 after the review of the first plan; the user accepted the review’s proposals (“go ahead update the plan”).

D2 overrides the CLAUDE.md working rule “until objective 3 is done, don’t restructure or edit the input files” — at the user’s explicit request, made together with D2 itself. WP01 updates CLAUDE.md in the same package that moves the files, so the working rule and the actual layout change together.

3 Hard cases

Report cases H1–H19 are open judgment calls: places where a label, a value or a cross-check did not resolve cleanly to one coding. Each is built with its recommended coding as DRAFT; the user confirms or flips it at gate G0. DECIDED cases (H15, H16, H18, H19) were already settled by the user decisions in Table 1 and are listed here for completeness and cross-reference, with an empty user note since no further input is expected.

Each case below gives: the question, the evidence for the recommended coding, the recommended (built) coding, the alternative, which packages build the coding, its status, and the user’s note (empty until G0).

3.1 H1 — Non-food consumption share

Case. Whether label #72, “Non-food consumption share”, is stored as its own series or derived from COICOP 1.

Evidence. Food share + non-food share sums to 0.98–1.02 across cells; non-food minus the sum of COICOP 2–13 sits in −0.02 to +0.03. This follows the standard’s existing precedent of not storing a separate “housing burden” indicator (data-standard.qmd line 73).

Recommended (built default). DERIVED, not stored as its own series: value = 1 − CONS_SH/COICOP_CP01.

Alternative. An aggregate qualifier COICOP_CP02T13 — needs an aggregate-category flag the standard does not have, and the closure check currently excludes aggregates.

Built by. WP08 (SERIES_PLAN.csv — no series row for label #72), WP09 (LEGACY_LABELS.csv assert_rule: ONE_MINUS:<label#>).

Status. DEFAULT.

User note. —

3.2 H2 — Own-production vs. market food share

Case. Whether label #77 “Own-production food share” and label #69 “Market food share” are a new qualifier on CONS_SH + COICOP 1, or two separate indicators.

Evidence. Own-production share + market share is less than the food share by 0.01–0.03 in SEN and 0.03–0.08 in GNB — the gap is gifts/in-kind acquisition, and there is no closure check across the three.

Recommended (built default). A new qualifier variable ACQ (acquisition mode) on CONS_SH + COICOP_CP01, categories ACQ_PURCH, ACQ_OWNPROD (DRAFT categories ACQ_GIFT, ACQ_INKIND registered but not populated).

Alternative. Two separate indicators, CONS_FOOD_OWN_SH and CONS_FOOD_MKT_SH.

Built by. WP06 (CL_QUAL_VAR.csv, CL_QUALIFIER.csv — the ACQ variable and its categories), WP08 (SERIES_PLAN.csv), WP09 (legacy maps).

Status. DEFAULT.

User note. —

3.3 H3 — Wage vs. non-wage employment

Case. Whether label #95 “Wage-employed” and label #73 “Non-wage employed” need a new breakdown variable or a derived indicator.

Evidence. Wage share + non-wage share sums to exactly 1.00 in every cell of both countries.

Recommended (built default). POP_SH with a new breakdown variable EMP_TYPE (categories EMP_TYPE_WAGE, EMP_TYPE_NONWAGE, ICSE-based).

Alternative. A single proportion indicator JOB_WAGE, with non-wage DERIVED as 1 − JOB_WAGE.

Built by. WP06 (CL_BRK_VAR.csv, CL_COMP_BREAKDOWN.csv — EMP_TYPE), WP08 (SERIES_PLAN.csv), WP09 (legacy maps).

Status. DEFAULT.

User note. —

3.4 H4 — “Employed”

Case. Whether label #26 “Employed (activ12m, 15–64)” also needs a derived “not employed” row.

Evidence. No cross-check issue found; the existing breakdown variable EMP_STATUS already has both categories (EMP_STATUS_EMPLOYED, EMP_STATUS_NOT_EMPLOYED — see the standard’s initial breakdown variables table, sec-initial-breakdowns), but only the employed category is populated by the legacy label.

Recommended (built default). Map to POP_SH with breakdown EMP_STATUS_EMPLOYED only; EMP_STATUS_NOT_EMPLOYED is never derived from it, since no legacy label provides an independent value to check against.

Alternative. None proposed in the report.

Built by. WP09 (LEGACY_LABELS.csv mapping only; no new codelist rows).

Status. DEFAULT.

User note. —

3.5 H5 — “HH workers” in trade/transport

Case. Whether labels #89 “Share of HH workers in trade/commerce” and #90 “…in transport” are children of EMP_SECTOR_SER or a new breakdown variable, and what “HH workers” means as a universe.

Evidence. Trade + transport is always ≤ services (gap 0.00–0.36 across cells), consistent with being subsets of it. The universe “HH workers” is not otherwise defined in the legacy labels.

Recommended (built default). POP_SH with a new breakdown variable EMP_ISIC (ISIC sections; register the full A–U set, publish sections G and H). Universe left TBD.

Alternative. Nest trade and transport as children of EMP_SECTOR_SER, or register them as separate JOB_* proportion indicators.

Built by. WP06 (CL_BRK_VAR.csv, CL_COMP_BREAKDOWN.csv — EMP_ISIC), WP08 (SERIES_PLAN.csv), WP09 (legacy maps).

Status. DEFAULT.

User note. —

3.6 H6 — “HH workers” informally employed

Case. Whether label #91 “Share of HH workers informally employed” is a new breakdown of the employed, or of wage employees only.

Evidence. Correlates with the non-wage share at r = 0.86–1.00, and sits 0.01–0.04 below it. This contradicts how the dashboard currently labels the equivalent figure, “Informal wage employment (% of wage)” (index.qmd:93), which implies a wage-employee universe.

Recommended (built default). POP_SH with a new breakdown variable EMP_FORMAL (categories EMP_FORMAL_Y, publish EMP_FORMAL_N), universe = employed persons, marked DRAFT.

Alternative. Universe = wage employees only, matching how the dashboard currently reads the figure.

Built by. WP06 (CL_BRK_VAR.csv, CL_COMP_BREAKDOWN.csv — EMP_FORMAL), WP08 (SERIES_PLAN.csv), WP09 (legacy maps).

Status. DEFAULT.

User note. —

3.7 H7 — Three electricity indicators

Case. Whether labels #1 “Access to electricity (grid, SDG 7.1.1)”, #17 “Connected to electricity grid (SDG7.1.1)” and #93 “Uses grid electricity” are three distinct indicators or duplicates of one concept.

Evidence. The three differ by country: GNB national totals are 0.23 / 0.27 / 0.26 (a narrow spread), but SEN’s are 0.68 / 0.98 / 0.66 (a 32-point spread) — the definitions clearly differ but are undocumented. On SEN, EN_GRID_CONN (#17) is 0.96–1.00 in every cell, including Q1 and Rural, which cannot be true grid connection of essentially all households. SDG 7.1.1 is normally population-based, so the weight needs confirming.

Recommended (built default). Three DRAFT codes (EN_ELEC_ACCESS, EN_GRID_CONN, EN_GRID_USE) cross-linked with related/related_note; a COMMENT override on the SEN EN_GRID_CONN rows noting the implausible near-universal value.

Alternative. Skip EN_GRID_CONN in both countries until its definition is documented.

Built by. WP07 (CL_INDICATOR.csv — the three codes and their related fields), WP09 (LEGACY_OVERRIDES.csv COMMENT on SEN EN_GRID_CONN).

Status. DEFAULT.

User note. —

3.8 H8 — Average outage duration (code)

Case. Whether label #3 “Average outage duration (code)” — a mean of an ordinal code, not a time unit — can be mapped at all.

Evidence. The value is explicitly a mean of a code (Annex 1 of the standard), not a duration; the code scale itself is not documented anywhere in the legacy files.

Recommended (built default). Map as DRAFT, unit_measure INDEX, checked with RANGE_NONNEG only; flagged for later deprecation in favour of shares by duration class once the code scale is documented.

Alternative. Skip #3 until the code scale is documented.

Built by. WP07 (CL_INDICATOR.csv — EN_OUTAGE_DUR_CODE, unit_measure INDEX), WP09 (legacy map).

Status. DEFAULT.

User note. —

3.9 H9 — Cooker “proxy”

Case. Whether label #86 “Proxy: owns gas/electric cooker (cuisin)” is mapped as a proxy for label #85 “Primary cooking fuel clean (gas/electricity)”, and whether the “proxy” wording belongs in the indicator name.

Evidence. SEN clean-cooking share is 0.73 nationally against a cooker-ownership share of only 0.04, and clean cooking is higher in Rural (0.76) than Capital (0.60) and higher for Q1 (0.79) than Q4 (0.57) — the reverse of what “clean cooking” should show, and implausible on its face.

Recommended (built default). EN_ASSET_COOKER, “proxy” dropped from the name, related = EN_COOK_CLEAN; both flagged for human review given the implausible pattern.

Alternative. Skip label #86 entirely.

Built by. WP07 (CL_INDICATOR.csv — name and related field), WP09 (legacy map, LEGACY_OVERRIDES.csv COMMENT).

Status. DEFAULT.

User note. —

3.10 H10 — Owner vs. owns enterprise

Case. Whether label #59 “HH has non-agric enterprise owner” and label #60 “HH owns a non-agric enterprise” are the same fact from two sources, or two different indicators.

Evidence. Label #60 equals 1 − (label #53, “HH has 0 HE”) exactly in every cell of both countries. Label #59 differs from #60 by −0.28 to +0.39, so it comes from a different source variable, not a rounding difference.

Recommended (built default). #60 is DERIVED (not stored); #59 is mapped as a new DRAFT indicator HE_HH_OWNER.

Alternative. Code #60 as POP_HH_SH with a new aggregate breakdown category HE_COUNT_1P (parent of HE_COUNT_1…HE_COUNT_4P).

Built by. WP07 (CL_INDICATOR.csv — HE_HH_OWNER), WP09 (LEGACY_LABELS.csv assert_rule: ONE_MINUS:<label#> for #60).

Status. DEFAULT.

User note. —

3.11 H11 — HE owner female / married

Case. Whether labels #67 “Main HE owner is female” and #68 “Main HE owner is married” are breakdown categories of POP_HE_SH or their own proportion indicators.

Evidence. No cross-check contradiction found; the choice is structural — the standard has no rule yet for “share as a breakdown vs. share as a proportion indicator” (see gap (o)/(t) discussion and Section 5 item 7 area).

Recommended (built default). POP_HE_SH with two new breakdown variables, HEO_SEX (categories HEO_SEX_F, publish HEO_SEX_M) and HEO_MSTAT (categories HEO_MSTAT_MARRIED, HEO_MSTAT_NOT_MARRIED), so either can also break down other HE indicators.

Alternative. Two proportion indicators, HE_OWNER_FEMALE and HE_OWNER_MARRIED.

Built by. WP06 (CL_BRK_VAR.csv, CL_COMP_BREAKDOWN.csv — HEO_SEX, HEO_MSTAT), WP08 (SERIES_PLAN.csv), WP09 (legacy maps).

Status. DEFAULT.

User note. —

3.12 H12 — HE external employees

Case. Whether label #38 “HE has external (non-HH) employees” can be mapped as-is.

Evidence. The share is 0.96 (SEN) / 1.00 (GNB) — impossible for “all HEs have external employees” when mean non-HH employees (label #71) is only 0.54/0.48. Label #74 “Number of employees in HE” does not equal #52 + #71 (residual −0.53 to +1.96 in SEN, −0.76 to +0.09 in GNB), so there is no additive check to fall back on.

Recommended (built default). Map DRAFT, universe TBD, with a COMMENT override noting the implausible near-universal value.

Alternative. Skip label #38.

Built by. WP07 (CL_INDICATOR.csv — universe_filter), WP09 (LEGACY_OVERRIDES.csv COMMENT).

Status. DEFAULT.

User note. —

3.13 H13 — ≥1 HH member covered

Case. Whether label #97 “≥1 HH member has health coverage (proxy social protection)” is a household-level indicator or a breakdown of label #62 “Has health insurance/coverage (couvmal)”.

Evidence. Always ≥ label #62 by 0.00–0.08, consistent with “at least one member” being a looser condition than the individual-level question.

Recommended (built default). A new household-level indicator SP_HEALTH_COV_HH; “proxy social protection” kept only in notes, not the name.

Alternative. POP_HH_SH with a new breakdown variable.

Built by. WP07 (CL_INDICATOR.csv — SP_HEALTH_COV_HH), WP09 (legacy map).

Status. DEFAULT.

User note. —

3.14 H14 — Internet access

Case. Whether label #58 “HH has internet access” is worth mapping at all.

Evidence. 0.00 or empty in every cell of both countries — implausible for SEN in particular, and carries no information.

Recommended (built default). SKIP.

Alternative. Map it with a COMMENT override instead of skipping.

Built by. WP09 (LEGACY_LABELS.csv, action SKIP).

Status. DEFAULT.

User note. —

3.15 H15 — Share indicators’ unit

Case. Whether population shares need one indicator (POP_SH) or several, split by the statistical unit of the breakdown behind them.

Evidence. A single POP_SH cannot keep one stat_unit: HE_COUNT breakdowns describe households (standard line 77) while POP_SH’s declared stat_unit is IND (standard line 386).

Decision. DECIDED by D4 (Table 1): three codes, POP_SH (IND), POP_HH_SH (HH), POP_HE_SH (HE), each with its matching weight.

Alternative (not taken). One POP_SH with stat_unit inferred from the breakdown’s describes field.

Built by. WP07 (CL_INDICATOR.csv — the three codes).

Status. DECIDED — D4.

User note. —

3.16 H16 — Departement sheet

Case. Whether to load any of the Departement sheet’s 82 labels.

Evidence. Its poverty totals disagree with ADM 1 (4.13M/7.88M vs 3.13M/6.52M poor), and several values that should match a shared indicator are impossible (HE has any credit access = 1.00 in every region; HH has 4+ HE = 0.80–1.00, though 0/1/2/3 already sum to about 1).

Decision. DECIDED by D3 (Table 1): skip all 82 labels.

Alternative (not taken). Keep the sheet’s two poverty rows as POV_HC with PPP_2017.

Built by. WP02 (standard text — removes the PPP_2017 exception and example row, closes open decision 9), WP09 (LEGACY_LABELS.csv, action SKIP).

Status. DECIDED — D3.

User note. —

3.17 H17 — Household-head age cutoff

Case. Where the boundary between Youth_HH and Older_HH falls, since the legacy files never document it.

Evidence. The dashboard currently labels Older_HH as “29+” (index.qmd:64), which contradicts the standard’s placeholder HHH_AGE_LT35/HHH_AGE_GE35 (standard lines 296, 905) and suggests a cutoff of 29 or 30, not 35.

Recommended (built default). DRAFT codes that stay renamable without becoming a new code (per the “never changes meaning” rule, standard line 373 — a DRAFT code can still be corrected); confirm the true cutoff with the producer before the codes go ACTIVE.

Alternative. Keep HHH_AGE_LT35/HHH_AGE_GE35 as written in the standard.

Built by. WP06 (CL_BRK_VAR.csv, CL_COMP_BREAKDOWN.csv — the HHH_AGE categories).

Status. DEFAULT.

User note. —

3.18 H18 — GNB Capital column

Case. Whether to keep the GNB National estimateCapital column, given it does not hold Bissau’s values.

Evidence. estimateCapital is byte-identical to ZAE estimateZonas_Costeiras_do_Sul on all 97 indicators, and matches SAB (Bissau) on only 9 of 97 rows — all rows that are constant everywhere anyway. Keeping it with AGG_SUM would fail: residence shares would sum to 1.24M poor at $4.20 against a national 1.09M.

Decision. DECIDED by D5 (Table 1): withheld — the whole column is absent as rows, registered in LEGACY_OVERRIDES.csv.

Alternative (not taken). Keep it with a COMMENT override, accepting that AGG_SUM would fail on it.

Built by. WP09 (LEGACY_OVERRIDES.csv, action WITHHOLD).

Status. DECIDED — D5.

User note. —

3.19 H19 — GNB cultivated area

Case. Whether to keep the 7 GNB Cultivated area (ha) cells above 100 ha outside the Capital column.

Evidence. Values reach the millions of “ha” (National Total 9.1M, Rural 10.8M, Male_HH 10.4M, Older_HH 10.5M, Q4 57.9M; ADM 1 Quinara 148.4M; ZAE Zonas_Costeiras_do_Sul 53.0M), against 1–15 ha for the rest of the indicator — almost certainly outlier records from a unit error in the microdata, each inflating the mean it enters.

Decision. DECIDED by D5 (Table 1): withhold these 7 cells (plus Capital’s own cell, already withheld under H18).

Alternative (not taken). Withhold the whole AGR_CULT_AREA indicator for GNB (26 rows), rather than just the affected cells.

Built by. WP09 (LEGACY_OVERRIDES.csv, action WITHHOLD, 7 rows).

Status. DECIDED — D5.

4 Gaps in the standard and their resolutions

The triage report found 25 places where data-standard.qmd v0.3 does not say enough to write the converter or the validator, lettered (a)–(y). The review of the first plan added (z) and (aa). Table 2 lists the resolution adopted for each. The column lists in this table are summaries; where they differ from contract/csv_headers.csv, the contract file is authoritative. WP02 writes all of these into data-standard v0.4; the user approves them at gate G1, before the metadata packages (WP04–WP10) begin. The package cards already carry the resolutions that each package needs.

Appendix: label triage

The machine-readable version of the label triage is contract/label_triage.csv, one row per legacy label of the current Excel tables; it is authoritative, and this appendix is its readable view. Every MAP row carries status = DRAFT: none of the 91 series it defines becomes ACTIVE until the user confirms or flips its hard case (Section 3) at gate G0.

Summary

The 97 National / ADM 1 / ZAE labels

Table 6 lists every label found identically on the National, ADM 1 and ZAE sheets of both Tables_SEN.xlsx and Tables_GNB.xlsx.
