## 0. Summary

The project's data standard v0.5 already follows the SDMX information model in spirit. This plan makes the files themselves SDMX 3.1 conformant while keeping CSV as the working format:

- Data files become **SDMX-CSV 2.1** data messages (three fixed leading columns, one column per DSD component, `NaN` for intentionally missing values).
- Reference metadata (surveys, sources, dashboard text, figures) becomes **SDMX-CSV 2.1 metadata messages**, generated from the existing registry CSVs.
- Structural metadata (agency, concepts, codelists, DSD, dataflow, MSD, metadataflow, provider schemes, provision agreements) is generated by R from the CSVs under `metadata/` into **one SDMX-ML 3.1 structure message**. No SDMX-JSON anywhere.
- The CSVs under `metadata/` remain the source of truth. A reverse importer turns an SDMX-ML export (for example from Fusion Metadata Registry after editing) back into the CSVs, so FMR can be used as an editor and validator.
- The dashboard reads the new files through one loader and stops reading `data_raw/`.
- The standard is revised to v0.6, metadata to 0.3.0, with every decision recorded (D27 to D46) and a conformance checklist with evidence.

Nothing under `data_raw/` changes. Every number in `data/` stays the same; the converter regenerates the files in the new layout and the independent reconciliation proves it.

> REVIEW QUESTION Q1 (D38). The rationale says a published file "is the complete replacement of that slice" and that only `I` is deprecated. The SDMX-CSV 2.1 data field guide says `R` replaces whole observations and "cannot be used to replace a whole dataset or a whole series", and lists both `I` and `A` as deprecated. Recommended: keep `R`; replace the rationale with "The guide recommends `R` for complete query responses (instead of the deprecated `I`; `A` is also deprecated). `R` replaces whole observations and merges attributes above observation level; it does not delete observations missing from the file. A consumer replacing a slice deletes it first; the published files contain no `D` rows." Section 2.3 states these semantics.
>
> REVIEW QUESTION Q2 (D39). The decision lets "any other measure or attribute" be empty, but `SERIES_ID`, `UNIT_MEASURE`, `OBS_STATUS` and `SOURCE_ID` are required on every row, and the guide reserves `NaN` for float and double components (`#N/A` for every other type). Recommended: "Any optional measure or attribute that a source cannot supply is left empty. Mandatory attributes are never empty." Rationale: "`NaN` is the intentionally-missing value for float/double components (`OBS_VALUE` is Double); `#N/A` is the value for other types and is not used." Section 2.3 states this rule.
>
> REVIEW QUESTION Q3 (D32). "SDMX forbids a semver artefact from referencing a legacy-versioned one" is a rule of the IM technical notes (Annex "Semantic Versioning", "Dependency Management"), not of the schemas, and the XSD forces the provision agreements to reference `DATA_PROVIDERS(1.0)` and `METADATA_PROVIDERS(1.0)`. Recommended: keep the decision (no structural reference to a global list); append to the rationale "The fixed-version organisation schemes (`(1.0)`) are the one exception, required by the XSD." Section 2.1 states the exception.
>
> REVIEW QUESTION Q4 (D31). Shipping `WB:AGENCIES` asserts an artefact in the World Bank's namespace. Section 2.1 now calls it a local placeholder that is never submitted to a registry and is replaced by the World Bank's own scheme at registration. Recommended: confirm; D31 unchanged.

## 2. Target design

### 2.1 Identity and versioning

- Agency `WB.AFW360`. Declared by a `WB:AGENCIES` agency scheme (fixed id, no version attribute in XML) containing `Agency id="AFW360"`, name "West Africa Micro Data 360 (AFW DIP/POV team)".
- The `WB:AGENCIES` scheme is a local placeholder so that `WB.AFW360` resolves in FMR, pysdmx and the XSD and URN checks. It asserts nothing in the World Bank's namespace, is never submitted to any registry, and is replaced by the World Bank's own scheme at registration. Before loading into a World Bank registry, check whether `WB:AGENCIES` already exists there; if it does, have `AFW360` added to it and drop the local copy.
- Semver dependency rule (IM technical notes, Annex "Semantic Versioning", "Dependency Management"; not enforced by the XSD): a semver artefact references only semver artefacts. Exception: references to items of the fixed-version organisation schemes (`AGENCIES`, `DATA_PROVIDERS`, `METADATA_PROVIDERS`, URN version `(1.0)`) are required by the XSD and allowed; the `SDMX.URN` check exempts them. Annotation values (`GLOBAL_CODE`, `SDMX_CROSS_DOMAIN_CONCEPT`) are not structural references.
- Every maintainable artefact: `agencyID="WB.AFW360"`, `version="0.3.0"` (from `metadata/VERSION`).
- URN form: `urn:sdmx:org.sdmx.infomodel.<package>.<Class>=WB.AFW360:<ID>(0.3.0)`; codes append `.<CODE>`.
- Short reference form used in CSV messages: `WB.AFW360:<ID>(0.3.0)`.
- Message header sender id: `WB_AFW360` (sender ids are plain IDs and cannot contain a dot).
- Artefact ids are NCNames: start with a letter, then letters, digits, `_` or `-`. Project code rules (upper case, at most 32 characters, no leading `_` except sentinels) are stricter and stay.

### 2.3 Data file: SDMX-CSV 2.1

Header and first row of `data/AFW360_HH_SEN_2021_SURVEY.csv` after the change (one line each; shown wrapped):

```

```

Rules:

- 37 columns in this order (D46). The key is the 18 dimensions plus `TIME_PERIOD` (19 columns). The header is one physical line; WP3a check 1 repeats it unwrapped. In the sample row `GEO = SN01` is the `CL_GEO` code of Dakar (ADM1); national totals use `GEO = _T`.
- `STRUCTURE` is always `dataflow`; `STRUCTURE_ID` is `WB.AFW360:AFW360_HH(<VERSION>)`; `ACTION` is `R` (D38). `R` replaces whole observations and merges attributes above observation level; it does not delete observations absent from the file (a consumer replacing a slice deletes it first with a `D` row of the partial key `REF_AREA`, `ESTIMATION`, `TIME_PERIOD`; the published files carry no `D` rows). `I` and `A` are deprecated in SDMX-CSV 2.1.
- `FREQ` is `A`.
- `OBS_VALUE` is `NaN` when `OBS_STATUS` is `O` or `M`; otherwise a number (D39). `NaN` is the SDMX-CSV intentionally-missing value for float and double components only (`#N/A` is the value for every other type and is not used). Optional measures and optional attributes are empty when not available. Mandatory attributes (`SERIES_ID`, `UNIT_MEASURE`, `OBS_STATUS`, `SOURCE_ID`) are never empty.
- Attributes attached to partial keys (`SERIES_ID`, `UNIT_MEASURE`) are replicated on every row and carry exactly one value per partial key across all data files (`SERIES_ID` per `INDICATOR` and the ten breakdown and qualifier dimensions; `UNIT_MEASURE` per `REF_AREA` and `INDICATOR`). Validator check `STRUCT.ATTR_LEVEL` (ERROR, WP4a) groups all rows of all files by each attribute's relationship dimensions and reports any group with more than one distinct value.
- Numbers use `.` as decimal separator, no thousands separator; unchanged.
- RFC 4180 quoting, written with `readr::write_csv(..., na = "")` (readr's default `NA` must not appear). UTF-8 without BOM, LF line endings (project convention, a documented deviation from RFC 4180, which specifies CRLF; the SDMX-CSV 2.1 guide does not address line endings or BOM).
- File names unchanged.
- Manifest keys: `dataflow` becomes `structure_id` (`WB.AFW360:AFW360_HH(0.3.0)`); a new key `sdmx_csv_version` = `2.1.0`; the other 15 keys unchanged.

### 2.5 Codelists and the CSV-to-SDMX mapping

Every `metadata/codelists/CL_*.csv` becomes a codelist `WB.AFW360:CL_*(0.3.0)`. Mapping (D41):

| CSV column | SDMX |
|---|---|
| `code` | `Code/@id` |
| `name_en` | `Name xml:lang="en"` |
| `definition_en` | `Description xml:lang="en"` (omitted when empty) |
| `parent` | `Parent` (same codelist) |
| `global_urn` | annotation type `GLOBAL_CODE`, value = the URN |
| `status`, `version_added`, `replaced_by`, `notes` | annotations `AFW_STATUS`, `AFW_VERSION_ADDED`, `AFW_REPLACED_BY`, `AFW_NOTES` |
| any other column | annotation `AFW_<COLUMN upper-cased>`, value = cell text as is (space-separated lists stay space-separated) |

Annotation form: `Annotation id="<type>"` with `AnnotationType` = type and `AnnotationValue` = value. Annotations are the first child of the code. Empty cells produce no annotation.

Special cases:

- `CL_GEO_SCHEME.csv` is keyed by `ref_area` + `code`; the SDMX code id is `<ref_area>_<code>` (for example `SEN_ADM1`) with the two parts also kept as annotations. The importer splits on the first underscore.
- Sentinels (D42): the generator appends `_T` ("Total") and `_Z` ("Not applicable") to `CL_GEO` (`_T`), `CL_SEX` and `CL_AGE` (`_T`, `_Z`), `CL_URBANISATION` (`_T`), `CL_COMP_BREAKDOWN` (`_T`), `CL_QUALIFIER` (`_Z`), reading the DSD CSV's `sentinel` column. Each carries an annotation `AFW_SENTINEL` = `Y`, which the importer uses to drop them, and a `GLOBAL_CODE` holding the full URN of the matching code in the list's own global counterpart where one exists: `CL_SEX` `_T`/`_Z` → `urn:sdmx:org.sdmx.infomodel.codelist.Code=SDMX:CL_SEX(2.1)._T` / `._Z`; `CL_AGE._T` → `...Code=IAEG-SDGs:CL_AGE(1.25)._T`; `CL_URBANISATION._T` → `...Code=IAEG-SDGs:CL_URBANISATION(1.10)._T`; `CL_COMP_BREAKDOWN._T` → `...Code=IAEG-SDGs:CL_QUANTILE(1.1)._T`. Where the own list has no such code (`CL_AGE._Z`, `CL_GEO._T`, `CL_QUALIFIER._Z`) the value is `...Code=SDMX:CL_SEX(2.1)._T` or `._Z`. Eight sentinel codes in all (`CL_GEO` 1, `CL_SEX` 2, `CL_AGE` 2, `CL_URBANISATION` 1, `CL_COMP_BREAKDOWN` 1, `CL_QUALIFIER` 1), each with one `GLOBAL_CODE`.
- `GLOBAL_CODE` and `global_urn` values are always full code URNs, `urn:sdmx:org.sdmx.infomodel.codelist.Code=<agency>:<id>(<version>).<code>`, never the short form.
- Derived codelists (D43): `CL_SERIES` from `plans/SERIES_PLAN.csv` (one code per distinct `series_id`, name = `name_en` of the `ALL` row, annotations `AFW_STATUS` from the `ALL` row); `CL_SOURCE` from `registries/SOURCES.csv` (name = `source_id`, description = `notes`); `CL_SURVEY` from `surveys/SURVEYS.csv` (name = `survey_name`); `CL_FIGURE` from `registries/FIGURES.csv` (name = `title_en`). Derived codelists carry only id, name, description and `AFW_STATUS`; everything else goes to metadatasets (2.7).

### 2.6 Concept scheme `CS_AFW360`

One concept per component id of 2.4 (`FREQ`, `REF_AREA`, ..., `OBS_COMMENT`; the five `COMP_BREAKDOWN_n` and five `MEASURE_QUAL_n` are separate concepts), plus one concept per metadata attribute of 2.7. - MSD `WB.AFW360:MSD_AFW360(0.3.0)` with four presentational parent attributes (`isPresentational="true"`, `minOccurs="0"`, `maxOccurs="1"`, no `LocalRepresentation`; the XSD default for `minOccurs` is 1 and each metadataset fills only one parent), each with one child per source column (minus the id and `status` columns); children have `TextFormat textType="String"`, `minOccurs="0"`, `maxOccurs="1"`:

  - Targets are whole artefacts, as the SDMX-CSV 2.1 metadata field guide defines them (`TARGET_TYPES` = a REST structure resource name, `TARGET_IDS` = `AGENCY:ID(VERSION)`); the guide has no item-level (single code) target form.   - Presentational parents have no column; only child attributes appear, as `<PARENT>.<CHILD>`. Files are written with `readr::write_csv(quote = "all", na = "")`, because the guide recommends quoting every textual value and all MSD attributes are `String`.
  - `MDSTRUCTURE` = `metadataflow`, `MDSTRUCTURE_ID` = `WB.AFW360:MDF_AFW360(0.3.0)`. Metadatasets are non-versioned (no version in the id).

## 3. Work packages

Conventions for every work package:

- **Implementer**: Opus unless the heading says Sonnet, fresh agent, prompt self-contained (the orchestrator pastes the WP text and the plan sections the WP names). Reads only the listed context; large files are read with `sed -n 'a,bp'` or `grep -n`, never whole. Test and validator output goes to `tmp/*.log` and only the tail or the failing lines are read. Target: under 100k tokens of context at the end. The implementer does not commit and does not edit `PROGRESS.md`; it returns a report of at most 40 lines: files changed, commands run with exit codes, surfaced points (facts that contradict this plan or the standard), and anything left undone.
- **Verifier**: Sonnet, fresh agent, under 60k tokens. Receives the WP's verification list verbatim and the repository path, nothing else. Runs every check, reports PASS or FAIL per check with the raw command and the decisive output lines, and never fixes anything. Self-reports by the implementer are not evidence.
- **Commit**: by the orchestrator, after the verifier passes, on branch `standard/v0.6-sdmx`, message given in the WP. The orchestrator records the commit hash in `PROGRESS.md`.
- **Size**: at most about 800 hand-written lines and 8 hand-written files per WP. Generated files (regenerated `data/`, `sdmx/`, `.docs/generated/`, the vendored XSDs, the fixture copy) do not count. Every verification list has at most 10 checks, each a command with its expected result.
- **Tests**: run one file with `Rscript -e "r<-as.data.frame(testthat::test_file('pipeline/tests/testthat/<name>.R'));cat('<name>',sum(r\$failed),sum(r\$error),'\n')"`, which prints `<name> 0 0` on success. Only WP3a edits `pipeline/tests/testthat/helper-*.R`; any other WP that needs a helper change reports it as a surfaced point.
- Paths are relative to the repository root. Commands run from the root in Git Bash. `tmp/` is the scratch folder (gitignored).
- Baseline checks that must stay green from WP4b on (WP3a, WP3b and WP4a may leave only the failures their own verification lists name): `Rscript pipeline/tests/testthat.R` (0 failures), `Rscript pipeline/validate.R --root . --out tmp/findings.csv` (exit 0), `Rscript pipeline/build_docs.R --root . --check` (exit 0). ## 4. Order and parallelism

```
WP0 -> (WP1 || WP2a -> WP2b || WP5a1)
WP1 + WP2b -> WP2c -> Gate 1 -> WP3a -> WP3b -> WP4a -> WP4b
WP3a + WP5a1 -> WP7 ; WP3a + WP2c -> WP9a -> WP9b -> WP9c
WP2c + WP3a + WP5a1 + WP7 -> WP5a -> WP5b -> (WP5c || WP6 || WP8a) ; WP4b + WP5c -> WP5d
WP8a -> Gate 2 -> (WP8b [-> WP8b2] | WP8c) ; WP6 -> WP8b, WP8c
every WP that ran -> (WP10a || WP10b || WP10c) -> WP11 -> Gate 3 -> merge
```

Two agents may run at the same time only when their file sets are disjoint (the lists above are designed so); `pipeline/tests/testthat/helper-*.R` belongs to WP3a alone. The orchestrator commits each verified WP before starting a WP that depends on it. Every "Depends on" line in section 3 and the `PROGRESS.md` table state this graph; there is no cycle.

## 5. Risks and contingencies

| Risk | Signal | Response |
|---|---|---|
| FMR 12.4 rejects SDMX-ML 3.1 namespaces | import error at WP8b | WP8b2: `--sdmx-ml-version 3.0` profile (2.13); canonical file stays 3.1 |
| FMR cannot run without Docker on this machine (database) | WP8a finds no portable database | Gate 2 defers; WP8c documents; files stay loadable |
| SDMX-CSV metadata files rejected by a second reader | FMR (WP8b) rejects a header or target | targets are already whole artefacts (2.7); WP5c adjusts the header form and records it as a surfaced point |
| `TIME_PERIOD` not accepted in an attribute relationship | XSD error in WP5b | not used in this design (only observation, dimension groups without time, dataflow); confirmed by WP5b check 2 |
| Dashboard numbers change after switch-over | WP9b check 2 (`differences: <n>` above 0) | the only intended changes are Guinea-Bissau reading its own data and formatting; anything else is a defect to fix before commit |
| Python package missing (lxml, matplotlib) | import error in WP5a, WP9a or WP9b | lxml lives only in `tools/verify/.venv` (WP7); matplotlib is installed in WP9a; the regression script uses the standard library |
| Agent context overrun | implementer report exceeds budget or degrades | orchestrator splits the WP along the file lists (handover, "Recording a split"); never widen context |
| Test suite runtime | slow full runs | implementers run the relevant test file (section 3 test command); verifiers run the full suite only where a WP says so |
| GeoPackage not byte-deterministic | WP11 step 1 shows `geo/boundaries/*.gpkg` modified | reported to the data lead at Gate 3; not a defect of the SDMX work |
