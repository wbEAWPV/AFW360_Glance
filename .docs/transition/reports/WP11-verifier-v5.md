## Deviations           (what the card said, what you did, why)
The acceptance script was already present on the branch (inherited from transition/main, per note (a) in the prompt: "THE ACCEPTANCE SCRIPT ON THIS BRANCH IS STALE"). Per step 3 ("review it against the card and keep or correct it"), I reviewed it against WP11.md as it reads on this branch and corrected the following, without touching any WP11 deliverable:
1. Removed `fix_manifest_long()`. Established what `make_data_fixture()` writes (per note (d)): read `pipeline/tests/testthat/helper-data-fixture.R` directly - it writes the `<stem>_manifest.csv` in the contract's long key/value form (16 rows; its own comment there says so explicitly). The inherited helper treated that already-correct table as if it were WIDE (one row, 16 named columns), collapsing it to a bogus 2-row table (`key`/`value` literally holding "key"/"value"). `pipeline/R/ctx.R`'s `build_ctx()` zips column 1 against column 2 into a named vector, so the bogus table has no `status` entry, which silently turns `CODES.DRAFT`'s `WARN` into `ERROR`. Confirmed by running the fixture build with and without the helper: without it, `CODES.DRAFT` gives 42 `WARN` (correct, manifest `status=DRAFT` found); with the old helper (tested separately, not committed), it would give `ERROR`. Removed the helper and used `make_data_fixture()`'s own output as-is.
2. Replaced `build_full_clean_root()` (untrimmed `SERIES_PLAN.csv`) and `build_small_clean_root()` (trimmed `SERIES_PLAN.csv`, untrimmed `LEGACY_LABELS.csv`) with one `build_clean_root()` that trims both files to the three named series, per plan commit 6d23f48 and note (b). The inherited `build_full_clean_root()` sidestepped the orphaned-reference bug by not trimming `SERIES_PLAN.csv` at all for A1, which is a different, larger fixture than "the clean fixture of step 2" A1 asks for (even though it also happened to be findings-clean). The inherited `build_small_clean_root()` used for A2/A3 never trimmed `LEGACY_LABELS.csv`, so its baseline already carried 88 `META.REFERENCE` ERRORs before any mutation - which would have let the `META.REFERENCE` mutation (case 11 of the A2 table) pass for the wrong reason (pre-existing noise, not the mutation's own effect). The unified fixture is properly clean and is used for A1 and as the shared base for every A2/A3 mutation.
3. Fixed A1's assertion from requiring overall `exit == 0` to requiring `exit != 2` (not a crash) plus 0 `ERROR` from `STRUCT`/`CODES`/`META` specifically. The card (as corrected by plan commit 00e61fc) explicitly scopes A1 to those three modules; `COVER`'s own ERRORs against this fixture are expected (WP08's fixture is not validator-clean and its card puts that out of scope) and correctly push the overall exit to 1. The inherited assertion would have failed A1 on every run for a reason outside WP11's control.
4. Renamed A3's injected crash function/module from `vc_zzz_forcedcrash` (module "zzz", sorts alphabetically after every real module) to `vc_moxie_crash` (module "MOXIE", sorts between META and RULE), and added an assertion that a check scheduled AFTER the crash point still ran. Since `validate.R` runs checks in alphabetical order (per the card's Interface section), a crash module named "zzz" can only ever prove that checks scheduled BEFORE it survived - never that "the other checks still run" holds for checks AFTER the crash point, which is the more meaningful half of that guarantee.
5. Broadened A5's implementer-report lookup from a single fixed filename to a glob over all `WP11-implementer*.md` reports. Not exercised in this run (A5 found 0 qualifying ERRORs), but a robustness fix: a later patch attempt's report often describes only what changed in that attempt, not a full restatement of the base report's defect list.
6. Fixed A6 to scope `testthat::test_dir()` to WP11's own file (`filter = "^validate-core$"`) instead of running the whole `pipeline/tests/testthat` directory. Per note (e): all four validator cards carry the identical "the unit tests pass" sentence and each card names the one file it owns (WP11's is `test-validate-core.R`); WP12's and WP13's own fixes to their test files live on branches not merged into this one, so an unscoped run would have failed inside files WP11 neither owns nor can edit.

None of these six corrections touch `pipeline/validate.R`, `pipeline/R/validate_structure.R`, `pipeline/R/validate_codes.R`, `pipeline/R/validate_metadata.R` or `pipeline/tests/testthat/test-validate-core.R` - only the acceptance script, which is the verifier's own deliverable across attempts.
