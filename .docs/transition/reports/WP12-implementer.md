## Deviations           (what the card said, what you did, why)
- **withheld_rows() skips a series absent from `required_rows()` entirely, rather than erroring.** The card says "Every (label, column) pair must give exactly one row; stop with an error if it gives none or several." Read completely literally, the `estimateCapital` override (`legacy_label = "*"`, meaning "every MAP label") expands to all 91 MAP series regardless of which series a *test* SERIES_PLAN was narrowed to (WP12.md step 2's own instruction: "Choose series that include AGR_CULT_AREA and one share"). On such a narrowed fixture, most of those 91 series have zero required rows at all (not just zero for the matched cut), and a strict interpretation throws on the very first fixture the card asks for. I read "stop with an error" as meaning "the (label, column) pair applies to a series that IS required here, but the cut/column match still fails" (a real metadata inconsistency) - not "a series this run's plan doesn't include at all" (simply not applicable). Implemented by checking `any(req$series_id == sid)` before applying the strict single-row match; only a series present in `req` at all is held to the "exactly 1" rule. This does not weaken the real-data check: on the full, real metadata (WP12.A3), every one of the 12 override rows still resolves with the exactly-91+7=98 matches the contract expects - no series is ever skipped there. Please confirm this reading is intended, or correct it if not - see Questions.
- **`file` for a finding is `data/<key>.csv`.** The card's "Findings format" says `file` is "the path relative to the root, with forward slashes" but does not spell out the data folder for WP12 specifically; `build_ctx()`'s `data`/`manifests` lists are keyed only by file stem (the original path passed to `read_std_csv()` is not retained). Inferred from `contract/expected_counts.csv` rows 27/32 ("data/AFW360_HH_SEN_2021.csv", "data/AFW360_HH_GNB_2021.csv") and from `helper-data-fixture.R`'s own `file.path(tmp_root, "data", paste0(stem, ".csv"))`. Both agree, so used `sprintf("data/%s.csv", key)`.
- **Cap ordering:** findings are grouped by `check_id`+`file` (in ascending order of that combined key) and, within each group, the kept 20 are ordered by `row_key`, with the SUMMARY row appended last in its group. The card only requires "the first 20 in row_key order" plus one SUMMARY finding: appended-last-per-group is a design choice for readability, not a requirement.

## Questions            (contract doubts, and anything only the user can decide)
- **Manifest CSV shape mismatch between three pieces of already-merged, non-WP12 infrastructure.** `contract/csv_headers.csv` (`AFW360_HH_<ISO3>_<YEAR>_manifest.csv`) and `pipeline/R/ctx.R`'s `build_ctx()` (confirmed by its own test, `test-ctx.R` "build_ctx reads a manifest's precision and other keys when present") both use a **long** 2-column `key,value` CSV, one row per of the 16 manifest keys. `pipeline/tests/testthat/helper-data-fixture.R`'s `make_data_fixture()` instead writes a **wide** 1-row, 16-column CSV (one column per key) - and `test-plan.R`'s own test of `make_data_fixture()` explicitly asserts that wide shape (`expect_equal(names(manifest), c("dataflow", ...))`, `expect_equal(nrow(manifest), 1L)`). Given `build_ctx()` parses `man_df[[1]]` as keys and `man_df[[2]]` as values (a long-format reader), calling it on a fixture built by `make_data_fixture()` silently produces a single, wrong manifest entry (`c(AFW360_HH = "TBD")`) instead of the 16 real keys - which would make every manifest-dependent check (`COVER.MANIFEST`, `COVER.SURVEY`, and the ref_area/time_period lookups `COVER.MISSING`/`COVER.EXTRA`/`COVER.WITHHELD_PRESENT` need) silently no-op on any fixture built the way WP12.md step 2 instructs. WP12 owns none of `ctx.R`, `helper-data-fixture.R`, `contract/csv_headers.csv` or their tests, so per COMMON.md section 2 this is registered, not fixed. `test-validate-coverage.R` works around it locally (`fix_manifest_long()`, documented in its header) by rewriting a fixture's manifest into the long form both the contract and `build_ctx()` expect, before calling `build_ctx()`. **This likely also affects WP11, WP13 and WP14**, which the same card wording points at the same `make_data_fixture()` + `build_ctx()` pairing for testing; whoever owns `helper-data-fixture.R` (WP08, most likely) should reconcile it with the contract and `ctx.R`.
- See the withheld_rows() "skips an absent series" deviation above - please confirm the reading, since it affects every wave-3 package that calls `withheld_rows()` on a narrowed test fixture.
