## Rules you need

**A series** is one indicator with its qualifier set and, for population shares, its defining breakdown category. The series `POP_HH_SH.HE_COUNT_0` is "share of households with no enterprise". Its `series_id` is the indicator, then the qualifier codes in ascending qualifier `slot_order`, then the defining breakdown, joined by `.`.

**A cut** is one way of splitting the population. It is a row of `TAB_PLAN`: a geography scheme, a set of residence codes, or breakdown variables.

**Required rows** (gap b) are every series, crossed with every cut that applies to it, crossed with the cells of that cut, minus anything the indicator excludes. `required_rows(meta, ref_area, time_period)` returns them by these steps:

1. Take the `SERIES_PLAN` rows and the `TAB_PLAN` rows whose `ref_area` is `ALL` or the country.
2. A cut applies to a series when all of these hold:
   - every variable in the cut's `comp_breakdowns` lists the indicator's `stat_unit` in its `CL_BRK_VAR.applies_to_units`;
   - none of those variables is the variable of the series' defining breakdown;
   - the cut's `themes` is `ALL` or contains the indicator's `theme`;
   - the cut's `sex` and `age` are both `_T`, or the indicator's `stat_unit` is `IND`.

   Geography and residence cuts apply to every unit (gap m).
3. The cells of a cut are the cross product of:
   - `GEO`: `_T`, or every `CL_GEO` code of the country in the cut's `geo_scheme`;
   - `URBANISATION`: `_T`, or each listed code;
   - `SEX` and `AGE`: `_T`, or each listed code;
   - every category of each variable in `comp_breakdowns`, found through `CL_COMP_BREAKDOWN.var_code`.
4. Drop the cells that use a variable or category listed in the indicator's `excluded_breakdowns`.
5. Write each row with the 18 key columns:
   - `DATAFLOW = AFW360_HH`, `REF_AREA`, `GEO`, `TIME_PERIOD`, `INDICATOR`;
   - `SEX` and `AGE`, which become `_Z` in place of `_T` when the indicator's `stat_unit` is not `IND` (gap l);
   - `URBANISATION`;
   - `COMP_BREAKDOWN_1…5`: the cut's categories plus the defining breakdown, ordered with `slot_sort()` and padded with `_T`;
   - `MEASURE_QUAL_1…5`: the series' qualifiers, ordered by qualifier `slot_order` and padded with `_Z`.
6. Add the two provenance columns `series_id` and `cut_id`, and sort by the key columns. The key is unique; the function stops if it is not.

`required_rows()` does **not** subtract withheld cells. That is the coverage check's job (WP12).

## Steps

1. Write `build_plans.R` (`--root`, `--out-root`). It writes two files:
   - `SERIES_PLAN.csv`: one row for each MAP row of the triage, with `series_id`, `ref_area = ALL`, `INDICATOR`, `MEASURE_QUALS`, `DEFINING_BREAKDOWN`, `status = DRAFT`, and `notes` holding the hard-case ID if there is one. Sort by `series_id`.
   - `TAB_PLAN.csv`: the rows of `contract/tab_plan.csv`, in that order, plus `status = DRAFT`.
2. Write `pipeline/R/plan.R` with `required_rows(meta, ref_area, time_period)` as specified above.
   - `meta` is the list from `load_metadata()`.
   - The function uses `SERIES_PLAN`, `TAB_PLAN`, `CL_INDICATOR` (`code`, `stat_unit`, `theme`, `excluded_breakdowns`), `CL_BRK_VAR`, `CL_COMP_BREAKDOWN`, `CL_QUAL_VAR`, `CL_QUALIFIER` and `CL_GEO`.
   - It stops with a clear message when one of them is missing.
3. Write the tests. The other packages' metadata files do not exist on your branch, so build `meta` inside the test from the contract seeds:
   - the four breakdown and qualifier lists from `codes.csv`;
   - `CL_GEO` from `geo_codes.csv`;
   - `CL_INDICATOR` from the triage (`code`, `stat_unit`, a `theme`, and an empty `excluded_breakdowns`);
   - your own two plan files.

   Test the total counts and the slot order of a crossed row. Also test, on a made-up two-series plan, that `excluded_breakdowns` and the `SEX`/`AGE` rule work.
4. Write `pipeline/tests/testthat/helper-data-fixture.R` with the function `make_data_fixture(tmp_root, ref_area, time_period = "2021", series_ids = NULL, value = "0.5")`. All six wave-3 packages build their tests on it.
   - `tmp_root` is a temporary root that already holds `metadata/` (from `make_temp_root()`).
   - If `series_ids` is given, the function first reduces `SERIES_PLAN.csv` in `tmp_root` to those series.
   - It writes `data/AFW360_HH_<ref_area>_<time_period>.csv`: every row of `required_rows()`, in the 26 DSD columns, with `OBS_VALUE = value`, `OBS_STATUS = A` and the other attributes empty.
   - It writes the manifest beside it, with the 16 keys `dataflow`, `dsd_version`, `metadata_version`, `ref_area`, `time_period`, `source_type`, `survey_id`, `precision`, `file_name`, `n_rows`, `producer`, `program`, `software`, `run_timestamp`, `status` and `notes`. It sets `precision = ROUNDED_2DP`, `status = DRAFT` and `source_type = SURVEY`.
   - It returns the path of the data file.
   - Test it on a temporary root whose `metadata/` you write from the seeds.
5. Run the script and the tests, and commit.

## Acceptance checks

- WP08.A1: `SERIES_PLAN` has one row for each MAP row of the triage (`SERIES.COUNT`), with `series_id`, `INDICATOR`, `MEASURE_QUALS` and `DEFINING_BREAKDOWN` equal to the triage's. `series_id` is unique and uses only `A–Z`, `0–9`, `_` and `.`.
- WP08.A2: `TAB_PLAN` equals `contract/tab_plan.csv` plus `status = DRAFT` (`META.TAB_PLAN` rows).
- WP08.A3: the headers equal `csv_headers.csv`.
- WP08.A4: with `meta` built from the seeds as in step 3, `required_rows(meta, "SEN", "2021")` has `DATA.SEN.ROWS` rows, and `required_rows(meta, "GNB", "2021")` has `GNB.MAPPED_CELLS` rows. Both have a unique 18-column key and no empty cell.
- WP08.A5: in those rows, `SEX` and `AGE` are `_Z` exactly when the indicator's `stat_unit` is not `IND`. The row of `POP_HH_SH.HE_COUNT_0` in the cut `QUINT` has `COMP_BREAKDOWN_1` starting with `QUINT_` and `COMP_BREAKDOWN_2 = HE_COUNT_0`. The row of `POV_HC.POVLINE_PL420.PPP_2021` has `MEASURE_QUAL_1 = POVLINE_PL420` and `MEASURE_QUAL_2 = PPP_2021`.
- WP08.A6: per country, the number of rows per `cut_id` equals the series count times the cut's cell count: `TOTAL` 1, `URB` 3, `HHH_SEX` 2, `HHH_AGE` 2, `QUINT` 5, `ADM1` 14 (SEN) or 9 (GNB), `ZONES` 6 (SEN only), `AEZ` 4 (GNB only).
- WP08.A7: the unit tests pass, and `build_plans.R --out-root <tempdir>` reproduces both files byte for byte.
- WP08.A8: `make_data_fixture()` on a seed-built temporary root, with `series_ids = c("POV_HC.POVLINE_PL420.PPP_2021", "POP_HH_SH.HE_COUNT_0")` and `ref_area = "GNB"`, writes a data file of 2 × 26 = 52 rows with the 26 DSD columns in order, and a manifest with the 16 keys whose `n_rows` is 52.
