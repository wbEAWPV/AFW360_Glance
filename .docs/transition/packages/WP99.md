# WP99 — Apply gate-G0 answers to the contract (conditional)

- **Wave:** 1, together with WP01 to WP03. **Runs only if** the user flipped at least one hard case at gate G0. **Slug:** `contract-flips`. **Acceptance script:** `pipeline/acceptance/wp99_contract-flips.R`.

## Goal

The user answered the hard cases before anything was built. Each flip is applied once, here, to the contract's seed files. Every later package then builds the flipped coding from the start, and nothing has to be patched afterwards.

## Read (exactly this)

- `packages/COMMON.md` and this card.
- Your prompt's `DECISIONS` block: the flipped cases with the user's answers, word for word.
- In `.docs/transition/decisions.qmd`, only the sections of the flipped cases. Find them with `grep -n "^## H" .docs/transition/decisions.qmd`.
- The seed rows that the flip touches, looked up through R: `contract/label_triage.csv` by `hard_case`, and `contract/codes.csv` and `contract/legacy_overrides.csv` as needed.

## Owned outputs

`.docs/transition/contract/label_triage.csv`, `codes.csv`, `legacy_overrides.csv`, `legacy_national_columns.csv`, `tab_plan.csv` and `expected_counts.csv`. This is the only package that may edit them, and it is the one exception to the rule in `COMMON.md` section 2 about `.docs/transition/**`.

## Rules you need

- Edit the seeds with a script (R, or Python's `csv` module) that changes only the rows it must. Never retype a label.
- Afterwards the files must still be UTF-8 with LF endings, and `git diff --stat` must show only the rows you meant to change.
- The series-ID rule: `series_id` is the indicator, then the qualifier codes in ascending qualifier `slot_order`, then the defining breakdown, joined by `.`.
- A label's action is `MAP`, `DUPLICATE_OF`, `DERIVED` or `SKIP`.
  - A `SKIP` row keeps `row_id`, `sheet`, `legacy_label`, `hard_case` and `notes`, and has every mapping column empty.
  - A `MAP` row needs every mapping column that the other `MAP` rows have. All labels of one indicator carry identical attributes.
- New codes follow the code pattern, are at most 32 characters long, are registered in `codes.csv` with `status = DRAFT`, and never reuse an existing code for a new meaning.
- `Rscript .docs/transition/contract/check_contract.R --root .` is the judge. It checks the seeds against each other and against the workbooks, and it recomputes every count.
  - After your edits, run it.
  - Its `EXPECTED.RECOMPUTED` line lists each count that changed, as "expected X, recomputed Y". Update `expected_counts.csv` to the recomputed values: the `expected` column, and the `source` column with a note such as `G0 flip H14`.
  - Update the formula text of the two `SOURCE.*.ACCOUNTING` rows too.
  - A count can keep its number while its content changes (one label leaves the mapped set and another enters). An unchanged number does not mean that there is nothing to do: the rows decide.
  - The seed `legacy_overrides.csv` has the 7 columns `ref_area, sheet, column, legacy_label, action, hard_case, reason`. It is not the 8-column `LEGACY_OVERRIDES.csv` that WP09 builds from it; keep the seed's header. A row added or deleted here changes `META.LEGACY_OVERRIDES`.
  - Repeat until it ends with "All contract checks passed."

For any other flip, or for an "Other" answer, design the coding from the alternative's text in `decisions.qmd` and the user's words. Keep it as small as the answer allows. If the answer is not precise enough to code, stop and report the question; do not guess.

## Steps

1. Apply each flip to the seeds.
2. Run `check_contract.R`, update `expected_counts.csv`, and rerun until it passes.
3. Search the cards for text that your flip makes stale: `grep -n "<old code or number>" .docs/transition/packages/*.md`. Do not edit the cards. List every hit in your report under "Deviations", as `card, line, old text, what it should say`. The orchestrator passes these notes to the affected agents.
4. Commit.

## Acceptance checks

- WP99.A1: `check_contract.R` exits 0.
- WP99.A2: `git diff transition-base HEAD --stat -- .docs/transition/contract/` lists only seed files. For every flipped case, the rows with that `hard_case` differ from `transition-base` as the answer requires, and the rows of every case that was not flipped are unchanged.
- WP99.A3: every changed `expected` value equals what `check_contract.R` recomputes. The acceptance script runs it and parses the `EXPECTED.RECOMPUTED` line.
- WP99.A4: every seed file's blob is UTF-8 without a BOM, has no CR byte, and keeps its original header.
- WP99.A5: the report lists the stale card text, or says "None" after a search whose command is shown.

## Verifier focus

Read the user's answers in your prompt and the flipped cases' sections in `decisions.qmd`. Judge whether the new coding is what the user asked for, the whole of it, and nothing more.
