# WP14 — Validator: assets and text

- **Wave:** 3. **Depends on:** wave 2 merged. **Slug:** `validator-assets-text`. **Acceptance script:** `pipeline/acceptance/wp14_validator-assets-text.R`.

## Goal

Checks for the boundary files, the two registries and the dashboard text.

## Read (exactly this)

- `packages/COMMON.md` and this card.
- The function signatures in `pipeline/R/io.R` and `ctx.R`, and in `helper-temp-root.R`. Use `grep -n "function("`.
- Through R: `GEO_SOURCES.csv`, `FIGURES.csv` and `TEXT.csv` (they are small), `head()` of `CL_GEO` and `CL_GEO_SCHEME`, and `sf::st_layers()` of one GeoPackage.

## Owned outputs

`pipeline/R/validate_assets.R`, `pipeline/R/validate_text.R` and `pipeline/tests/testthat/test-validate-assets-text.R`.

## Interface

- Your functions are named `vc_asset_<check>(ctx)` and `vc_text_<check>(ctx)`.
  - Each returns a tibble with the columns `check_id, severity, file, row_key, message`. Zero rows means pass.
  - `ctx` is the list from `build_ctx()`.
  - `check_id` is `ASSET.<NAME>` or `TEXT.<NAME>`.
- `pipeline/validate.R` (WP11, built at the same time as your package) finds your functions by name. Do not write an entry point.
- These checks need no data file, so they also run with `--metadata-only`.

**Findings format** (word for word the same on the cards WP11 to WP14):

- `file` is the path relative to the root, with forward slashes.
- `row_key`:
  - for a data row, the 18 key values joined by one space;
  - for a row of a metadata or content CSV, `<column>=<value>` of the column or columns that identify the row, joined by one space (`code=URB`, or `ref_area=GNB sheet=ZAE column=estimateEst`);
  - for a feature of a GeoPackage, `layer=<layer> geo_code=<code>`;
  - empty for a finding about a whole file.
- The cap: when one check has more than 20 findings for one file, keep the first 20 in `row_key` order, and add one finding with the same `check_id` and severity, an empty `row_key`, and the message `SUMMARY: <n> findings in total, 20 shown`.

## Rules you need

- File paths in the registries are relative: `GEO_SOURCES.file` to `geo/boundaries/`, `FIGURES.file` to `assets/figures/`, and `TEXT.file` to `content/text/`.
- Boundary layers carry the fields `geo_code`, `ref_area`, `scheme` and `name`. `CL_GEO` is authoritative for names, so a different `name` is a warning.
- Only schemes with `CL_GEO_SCHEME.has_geometry = Y` need polygons. The others are skipped silently.
- Read layers with `sf::sf_use_s2(FALSE)`. Validity is GEOS validity (`sf::st_is_valid`).
- Text is Markdown limited to paragraphs, emphasis, links, lists and footnotes. There is no raw HTML and no chunk syntax.
- The `{{…}}` syntax for live numbers is still a sketch (open decision 10). Do not resolve it; only flag it.

| `check_id` | Severity | Rule |
|---|---|---|
| `ASSET.FILE_MISSING` | ERROR | A `GEO_SOURCES` or `FIGURES` row points at a file that does not exist. |
| `ASSET.SHA256` | ERROR | The file's sha256 differs from the registry's. |
| `ASSET.LAYERS` | ERROR | The GeoPackage's layers differ from the row's `layers` field. |
| `ASSET.CRS` | ERROR | A layer is not EPSG:4326. |
| `ASSET.GEO_CODE` | ERROR | A feature's `geo_code` is not in `CL_GEO` with the same `ref_area` and `scheme`. |
| `ASSET.MISSING_GEOMETRY` | ERROR | A `CL_GEO` code of a scheme with `has_geometry = Y` has no feature in its `source_id` file and `geom_layer`. |
| `ASSET.DUPLICATE_FEATURE` | ERROR | Two features share one `geo_code` in a layer. |
| `ASSET.INVALID_GEOMETRY` | ERROR | A geometry is not valid. |
| `ASSET.NAME_MISMATCH` | WARN | A feature's `name` differs from `CL_GEO.name_en`. |
| `TEXT.BODY_FILE` | ERROR | A `TEXT.csv` row does not have exactly one of `body` and `file` filled. |
| `TEXT.FILE_MISSING` | ERROR | The referenced Markdown file does not exist. |
| `TEXT.LINEBREAK` | ERROR | A `body` contains a line break. |
| `TEXT.HTML` | ERROR | A `title`, a `body` or a referenced file contains raw HTML or chunk syntax: an HTML tag (`<` followed by a letter or `/`), `{python}`, `Markdown(`, or a line that starts with `#|`. |
| `TEXT.REFERENCE` | WARN | A `{{…}}` reference is present; it is reported, not resolved. |
| `TEXT.TBD` | WARN | A `body` is `TBD`. |

## Steps

1. Implement the two modules.
2. Write the tests on `make_temp_root(root)`, a copy of the real `metadata/`, `content/`, `geo/` and `assets/`. For geometry mutations, read a layer with sf, change it, and write it back to the temporary GeoPackage. For the self-intersecting polygon, build a bow-tie: `st_polygon(list(rbind(c(0,0), c(1,1), c(1,0), c(0,1), c(0,0))))`. Write with `st_write(..., layer = <layer>, delete_layer = TRUE, quiet = TRUE)`, so that the other layers stay as they are. Update the registry's sha256 in the temporary copy where the mutation is not about the checksum, so that each mutation triggers only its own check.
3. Run your functions on the real repository root. For every `ERROR`, decide whether your check or the asset is wrong. Fix the check when it is yours. If the asset or registry is wrong, do not edit it; list it under "Questions".

## Acceptance checks

- WP14.A1: on the unmodified temporary copy, your functions return 0 `ERROR`.
- WP14.A2: each mutation below gives exactly its `check_id`:
  - a byte appended to a GeoPackage gives `ASSET.SHA256`;
  - a feature's `geo_code` set to `SN99` gives `ASSET.GEO_CODE`;
  - one ADM1 feature removed gives `ASSET.MISSING_GEOMETRY`;
  - a feature duplicated gives `ASSET.DUPLICATE_FEATURE`;
  - a bow-tie polygon gives `ASSET.INVALID_GEOMETRY`;
  - the figure file deleted gives `ASSET.FILE_MISSING`;
  - a `TEXT` row with both `body` and `file` gives `TEXT.BODY_FILE`;
  - `about.md` deleted gives `TEXT.FILE_MISSING`;
  - `<b>x</b>` in a body gives `TEXT.HTML`.
- WP14.A3: on the real repository root, there are 0 `ERROR`, or every `ERROR` is listed in the implementer's report as an asset defect, with the file and the rule. The rows with `body = TBD` give `WARN TEXT.TBD`.
- WP14.A4: a scheme with `has_geometry = N` produces no finding.
- WP14.A5: the unit tests pass.

## Verifier focus

Build the bow-tie yourself and confirm that it is caught. Confirm that a mutation of the checksum alone does not also trigger geometry findings.
