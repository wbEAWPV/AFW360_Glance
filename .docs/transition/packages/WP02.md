# WP02 — Data standard v0.4

- **Wave:** 1. **Depends on:** WP00. **Slug:** `standard-v04`. **Acceptance script:** `pipeline/acceptance/wp02_standard-v04.R`.
- **Two stages, two agents, one branch.** Stage A creates `transition/wp02-standard-v04` and applies the decisions. Stage B starts when stage A reports `DONE`: it runs `git switch transition/wp02-standard-v04` (it does not create a branch) and applies the gap resolutions on top. One verifier checks the result after stage B. Your prompt says which stage you are.

## Goal

Bring `.docs/data-standard.qmd` into line with the decisions and the gap resolutions, so that the standard, the contract and the code agree. The file is split over two agents only to keep each session small.

## Read (exactly this)

- `packages/COMMON.md` and this card.
- `.docs/data-standard.qmd`, whole. It needs two reads; this is the one package that may read it whole.
- From `.docs/transition/decisions.qmd`, only your stage's section. Find the line ranges with `grep -n "^# " .docs/transition/decisions.qmd`.
  - Stage A: "Decisions taken".
  - Stage B: "Gaps in the standard and their resolutions".
  - Never read "Hard cases" or the appendix.
- Stage B also reads the header rows of the files it describes: `SERIES_PLAN.csv`, `LEGACY_LABELS.csv`, `LEGACY_COLUMNS.csv`, `LEGACY_OVERRIDES.csv` and the validator findings, filtered from `contract/csv_headers.csv` as in `COMMON.md` section 3.

## Owned outputs

`.docs/data-standard.qmd`, and one report per stage (`reports/WP02-implementer-A.md`, `reports/WP02-implementer-B.md`).

## Rules for both stages

- Edit in place with small, exact replacements. Do not rewrite sections that no decision or gap touches.
- Keep every existing `{#sec-…}`, `{#tbl-…}` and `{#lst-…}` ID. Add new IDs where you add sections.
- Write no rule that is not backed by a decision (D) or gap ID. If a resolution is unclear, or contradicts the contract, report it; do not improvise.
- When a list of columns is needed, take the names and their order from `contract/csv_headers.csv`.
- After your edits, run `env -u QUARTO_R QUARTO_PYTHON="C:/WBG/Python313/python.exe" quarto render .docs/data-standard.qmd 2>&1 | tail -n 5`, confirm that it succeeds, and delete the rendered `.html` and `_files/`.
