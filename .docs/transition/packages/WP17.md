# WP17 — Final audit

- **Wave:** after the wave-3 integration. **Depends on:** wave 3 integrated. **Slug:** `final-audit`. **Acceptance script:** `pipeline/acceptance/wp17_final-audit.R`.
- **Verifier only.** This package has no implementer: its "deliverable" is the whole of `transition/main`. One verifier agent runs it, with `{SOURCE_BRANCH} = transition/main` and `{VERIFY_BRANCH} = transition/wp17-final-audit-v<K>` (`v1` on the first run; a rerun after a fix gets `v2`).

## Goal

An independent check, before gate G2, that the finished repository meets every target of `contract/expected_counts.csv`, and that the validator and the reconciliation tool pass on the real data. The numbers shown to the user at G2 come from this audit, not from the agents that built the pieces.

## Read (exactly this)

- `packages/COMMON.md` and this card.
- `contract/expected_counts.csv`: the columns `check_id`, `expected` and `tolerance` only. It has 64 rows; print it in three pieces.
- `.docs/transition/reports/WAVE3-integration.md`. It is short.
- `metadata/registries/GEO_SOURCES.csv` through R, the columns `source_id`, `ref_area`, `file` and `layers`: `file` is relative to `geo/boundaries/`, and the `GEOM.*` targets count the features of the layers `adm0` and `adm1`.
- Never read the findings CSV or the reconciliation cells CSV whole. Use `table()` and `head()`.

## Owned outputs

`pipeline/acceptance/wp17_final-audit.R` and `.docs/transition/reports/WP17-verifier-v1.md`. Write nothing else.

## What the script checks

Read `expected_counts.csv` and check **every row** within its tolerance. Print one `CHECK <check_id> PASS|FAIL expected=<e> actual=<a>` line per row. Take the actual values from these sources:

| `check_id` | Actual value |
|---|---|
| `CELLS.*` | Counted from `data_raw/tables/*.xlsx` with readxl (`col_types = "text"`): the data columns times the rows, and the non-empty and empty cells |
| `LABELS.SHARED`, `LABELS.DEPARTEMENT`, `LABELS.TOTAL`, `META.LEGACY_LABELS` | Rows of `LEGACY_LABELS.csv` with `sheet = *`, with `sheet = Departement`, and all rows |
| `SERIES.COUNT`, `META.SERIES_PLAN` | Rows of `SERIES_PLAN.csv` |
| `INDICATOR.CODES`, `META.CL_INDICATOR` | Rows of `CL_INDICATOR.csv` |
| Other `META.*` | Row counts of the named file. `META.SMALL_CODELISTS` is the number of these files that exist: `CL_SEX`, `CL_AGE`, `CL_URBANISATION`, `CL_OBS_STATUS`, `CL_THEME`, `CL_STAT_UNIT`, `CL_STATISTIC`, `CL_WEIGHT` and `CL_UNIT`. |
| `DATA.SEN.*`, `GNB.DATA.*` | Rows of the data files, by `OBS_STATUS` |
| `GNB.MAPPED_CELLS`, `GNB.WITHHELD_CELLS`, `SOURCE.*.ACCOUNTING`, `DEPARTEMENT.SKIPPED` | From a fresh reconciliation cells CSV: counts by `class`. Mapped cells are converted plus withheld. An accounting check passes when the classes on the three sheets sum to the number of source cells. |
| `POVNUM.*` | `OBS_VALUE / 1000000` of the `POV_NUM` row at the national total (`GEO`, `URBANISATION` and every breakdown slot `_T`), for the line and country in the ID |
| `GEOM.*` | Feature counts of the GeoPackage layers |
| `LEGACY.FILES` | The tracked files under `data_raw/`, not counting `README.md` and `CHECKSUMS.sha256` |

Then add these checks of your own:

- WP17.V1: `Rscript pipeline/validate.R --root . --out <tempfile>` exits 0, and the findings hold 0 `ERROR`.
- WP17.V2: every `WARN` finding has one of the expected `check_id` values: `CODES.DRAFT`, `META.TBD`, `META.SLOT_ORDER_TIE`, `RULE.AGG_SKIPPED`, `TEXT.TBD`, `TEXT.REFERENCE`, `ASSET.NAME_MISMATCH`. Print the count per `check_id`.
- WP17.V3: `Rscript pipeline/reconcile.R --root . --out <tempfile> --csv <tempfile>` exits 0.
- WP17.V4: `Rscript pipeline/convert_legacy.R --root . --country ALL --timestamp 2026-01-01T00:00:00Z --out-root <tempdir>` reproduces the four committed files in `data/` byte for byte.
- WP17.V5: every row of every data file and codelist has `status` or manifest status `DRAFT`. Nothing is `ACTIVE`.
- WP17.V6: `sha256sum -c data_raw/CHECKSUMS.sha256` passes for all 122 files.

Do not call `run_all.R` from this script; `run_all.R` calls it. The script writes only to temporary files.

## Report

Use the verifier report format of your prompt. Add a table "Targets" with every `check_id`, its expected and actual values, and PASS or FAIL. Add a table "Warnings" with the count per `check_id`. The orchestrator shows these two tables to the user at G2.

## Verdict

`VERDICT: PASS` only if every row passes. On `FAIL`, name for each failure the package that owns the wrong file (look it up in `contract/output_ownership.csv`), so that the orchestrator can launch a patch agent.
