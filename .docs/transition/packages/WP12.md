# WP12 — Validator: coverage and values

- **Wave:** 3. **Depends on:** wave 2 merged. **Slug:** `validator-coverage`. **Acceptance script:** `pipeline/acceptance/wp12_validator-coverage.R`.

## Goal

The checks that a data file holds exactly the rows it must, and that each value and its attributes are well formed.

## Read (exactly this)

- `packages/COMMON.md` and this card.
- The function signatures in `pipeline/R/io.R`, `ctx.R` and `plan.R`, and in the two test helpers. Use `grep -n "function("`; do not read the files whole.
- Through R, `head()` of `metadata/plans/LEGACY_OVERRIDES.csv`, `LEGACY_COLUMNS.csv` and `LEGACY_LABELS.csv`, and of `metadata/surveys/SURVEYS.csv`.

## Owned outputs

`pipeline/R/validate_coverage.R`, `pipeline/R/validate_values.R` and `pipeline/tests/testthat/test-validate-coverage.R`.

## Interface

- Your functions are named `vc_cover_<check>(ctx)` and `vc_value_<check>(ctx)`.
  - Each returns a tibble with the columns `check_id, severity, file, row_key, message`. Zero rows means pass.
  - `ctx` is the list from `build_ctx()`: `root`, `meta`, `data`, `manifests`, `precision` and `opts`.
  - `check_id` is `COVER.<NAME>` or `VALUE.<NAME>`.
- `pipeline/validate.R` (WP11, built at the same time as your package) finds your functions by name. Do not write an entry point.
- With no data in `ctx`, every function returns zero rows.
- Test by sourcing your module and calling the functions directly on `build_ctx(tmp, data_files)`.

**Findings format** (word for word the same on the cards WP11 to WP14):

- `file` is the path relative to the root, with forward slashes.
- `row_key`:
  - for a data row, the 18 key values joined by one space;
  - for a row of a metadata or content CSV, `<column>=<value>` of the column or columns that identify the row, joined by one space (`code=URB`, or `ref_area=GNB sheet=ZAE column=estimateEst`);
  - for a feature of a GeoPackage, `layer=<layer> geo_code=<code>`;
  - empty for a finding about a whole file.
- The cap: when one check has more than 20 findings for one file, keep the first 20 in `row_key` order, and add one finding with the same `check_id` and severity, an empty `row_key`, and the message `SUMMARY: <n> findings in total, 20 shown`.

## Rules you need

**Required rows.** `required_rows(meta, ref_area, time_period)` from `plan.R` returns every row the plan demands, with the provenance columns `series_id` and `cut_id`. It does not subtract withheld cells.

**Withheld cells** (decision D5). A `LEGACY_OVERRIDES` row with `action = WITHHOLD` names legacy cells: `ref_area`, `sheet`, `column` and `legacy_label`, where `*` means every one and sheet `*` means `National`, `ADM 1` and `ZAE`. Translate them to required rows in two steps:

- The label gives the series, through `LEGACY_LABELS.series_id`. A `*` label means every `MAP` label.
- The (sheet, column) gives the cell, through `LEGACY_COLUMNS`. Its `cut_id` selects the cut. Within the series' required rows of that cut, the cell is the one row that matches the code the `LEGACY_COLUMNS` row fills: its `GEO`; or its `URBANISATION`; or its `COMP_BREAKDOWN` code in any breakdown slot. The series' own defining breakdown sits in another slot and plays no part in the match (for `POP_HH_SH.HE_COUNT_0` in the column `estimateFemale_HH`, the row holds both `HE_COUNT_0` and the column's code; match on the column's code). For the cut `TOTAL`, it is the single total row. Every (label, column) pair must give exactly one row; stop with an error if it gives none or several.

The expected rows are the required rows minus the withheld rows. `GNB.WITHHELD_CELLS` in `expected_counts.csv` says how many rows are withheld for GNB; SEN has none.

**The checks:**

| `check_id` | Severity | Rule |
|---|---|---|
| `COVER.MISSING` | ERROR | An expected row is absent. A cell with no value is a row with `OBS_STATUS = O`, never an absent row. |
| `COVER.EXTRA` | ERROR | A row is not in the required set. |
| `COVER.WITHHELD_PRESENT` | ERROR | A withheld row is present. |
| `COVER.MANIFEST` | ERROR | The manifest is missing; or one of its 16 keys is missing; or `n_rows`, `ref_area`, `time_period` or `file_name` disagree with the file. The keys are `dataflow`, `dsd_version`, `metadata_version`, `ref_area`, `time_period`, `source_type`, `survey_id`, `precision`, `file_name`, `n_rows`, `producer`, `program`, `software`, `run_timestamp`, `status` and `notes`. |
| `COVER.SURVEY` | ERROR | `SURVEYS.csv` has no row with the manifest's `survey_id`, or that row's `ref_area` or `time_period` differs. |
| `VALUE.NUMERIC` | ERROR | A filled `OBS_VALUE` is not a plain decimal number. Scientific notation is an error. |
| `VALUE.RANGE` | ERROR | `OBS_VALUE` lies outside the indicator's `valid_min` or `valid_max`. An empty bound means unbounded. Values are in base units. |
| `VALUE.STATUS_EMPTY` | ERROR | `OBS_VALUE` is empty although `OBS_STATUS` is `A` or `E`, or filled although it is `O` or `M`. |
| `VALUE.LEGACY_EMPTY` | ERROR | In a `ROUNDED_2DP` file, an `O` row whose `OBS_COMMENT` does not start with `LEGACY_EMPTY:` (decision D9). |
| `VALUE.SE_CI` | ERROR | `STD_ERR < 0`, or `OBS_VALUE` lies outside `CI_LOWER` to `CI_UPPER`, where these are filled. |
| `VALUE.N` | ERROR | In an `EXACT` file: `N_OBS` is missing or not a non-negative integer, `N_POP` is missing or negative, or `N_OBS = 0` without status `O`. In a `ROUNDED_2DP` file these columns are exempt; give one `INFO` finding per file that says so. |

Keep findings few: apply the cap of the findings format.

## Steps

1. Implement the two modules. Keep `withheld_rows(meta, ref_area, time_period)` as a separate, tested function in `validate_coverage.R`.
2. Write the tests on a temporary copy of the real metadata: `make_temp_root()`, then `make_data_fixture(tmp, "GNB", series_ids = …)`. Choose series that include `AGR_CULT_AREA` and one share, so that withheld cells occur. The fixture writes every required row, so delete the withheld rows from the fixture file to get a clean start. Then mutate one thing per test.
3. Compute the withheld rows for GNB on the real metadata and compare the count with `GNB.WITHHELD_CELLS`. If they differ, find out whether your translation or the metadata is wrong. If the metadata is wrong, do not edit it; report it under "Questions".

**No real data files exist yet.** The converter (WP15) is built at the same time as your package, so you test on fixtures only. The wave-3 integrator runs your checks on the real data files; if they give findings, a patch agent of your package gets them. Write `VALUE.LEGACY_EMPTY` exactly as stated: the comment starts with the 13 characters `LEGACY_EMPTY:`.

## Acceptance checks

- WP12.A1: on the clean fixture, your functions return 0 `ERROR`.
- WP12.A2: each mutation below gives exactly its `check_id`:
  - a row deleted gives `COVER.MISSING`;
  - a row added with an unplanned breakdown gives `COVER.EXTRA`;
  - a withheld row added back gives `COVER.WITHHELD_PRESENT`;
  - the manifest's `n_rows` changed gives `COVER.MANIFEST`;
  - the manifest's `survey_id` set to `XXX` gives `COVER.SURVEY`;
  - a share set to `1.3` gives `VALUE.RANGE`;
  - a value `1e-3` gives `VALUE.NUMERIC`;
  - an `O` row with a value, and an `A` row without one, each give `VALUE.STATUS_EMPTY`;
  - an `O` row with an empty comment gives `VALUE.LEGACY_EMPTY`.
- WP12.A3: on the real metadata, `withheld_rows(meta, "GNB", "2021")` has `GNB.WITHHELD_CELLS` rows, and `withheld_rows(meta, "SEN", "2021")` has 0. The number of required rows minus the withheld rows equals `GNB.DATA.ROWS`.
- WP12.A4: with `ctx$data` empty, every function returns zero rows and does not fail.
- WP12.A5: the unit tests pass.
