# WP07 — Indicator dictionary

- **Wave:** 2. **Depends on:** wave 1 merged, and gate G1. **Slug:** `dictionary`. **Acceptance script:** `pipeline/acceptance/wp07_dictionary.R`.

## Goal

`CL_INDICATOR.csv`: one row for each indicator code that the label triage uses (`INDICATOR.CODES` in `expected_counts.csv`, currently 62). A script takes the mechanical columns from the triage, and you write the text.

## Read (exactly this)

- `packages/COMMON.md` and this card.
- From `contract/label_triage.csv`, only the rows with `action == "MAP"`, in pieces of at most 30 rows:
  - first `INDICATOR`, `legacy_label`, `hard_case`;
  - then `INDICATOR`, `notes`.

  You write from these. Never print all 26 columns.
- The `CL_INDICATOR.csv` rows of `contract/csv_headers.csv` (37 columns).

## Owned outputs

- `pipeline/bootstrap/build_indicators.R` and `pipeline/bootstrap/text/indicators_text.csv`
- `metadata/codelists/CL_INDICATOR.csv`

## Rules you need

**An indicator code names a measure, not a variant of it.** The poverty rate at any line is `POV_HC`; the line and the PPP round are qualifiers. A consumption share is `CONS_SH`, with the COICOP division as a qualifier. A population share is one of three codes, chosen by what is counted (decision D4): `POP_SH` for individuals, `POP_HH_SH` for households, `POP_HE_SH` for enterprises. The group itself is named by a breakdown category.

**Columns the script derives.** Your text file has none of these.

| Column | Rule |
|---|---|
| `code` | The distinct `INDICATOR` values of the MAP rows |
| `stat_unit`, `statistic`, `weight`, `ref_period`, `unit_measure`, `unit_denom`, `unit_time`, `price_basis`, `display_as`, `decimals`, `valid_min`, `valid_max` | Copied from the triage. They are identical across all labels of one indicator; the script stops if they are not. |
| `universe_unit` | Equals `stat_unit` |
| `theme` | `POV` for `POV_HC` and `POV_NUM`; `CONS` for `CONS_SH`; `POP` for `POP_SH`, `POP_HH_SH` and `POP_HE_SH`; otherwise the part of the code before the first `_` (`HE`, `AGR`, `EN`, `HOUS`, `SHK`, `SP`) |
| `qualifiers` | `_Z` when no series of the indicator has `MEASURE_QUALS`. Otherwise one `VAR:CODE,CODE` entry for each qualifier variable that its series use: the variables in ascending qualifier `slot_order`, the codes in the seed's `order`, the entries separated by one space. Example: `POVLINE:POVLINE_PL300,POVLINE_PL420 PPP:PPP_2021`. A code's variable comes from `var_code` in `contract/codes.csv`. |
| `checks` | The tokens below, in this order, separated by one space |
| `excluded_breakdowns`, `price_ref_year`, `replaced_by` | Empty |
| `owner` | `AFW DIP/POV team` |
| `status`, `version_added` | `DRAFT`, `0.1.0` |

**`checks` tokens:**

1. `RANGE_0_1` when `unit_measure` is `SHARE`; otherwise `RANGE_NONNEG` when `valid_min` is `0`; otherwise nothing.
2. `AGG_SUM` when `statistic` is `TOTAL`; otherwise `AGG_BRACKET`. The one exception is `EN_OUTAGE_DUR_CODE`, which gets no aggregation token (hard case H8).
3. `MONOTONE_IN:POVLINE` when the indicator's series use a `POVLINE_*` qualifier.
4. `SUM_TO_1_OVER:COICOP` for `CONS_SH`.
5. `SUM_TO_1_OVER_BRK` for `POP_SH`, `POP_HH_SH` and `POP_HE_SH`.

**Columns you write** (`indicators_text.csv`, one row per code):

- `name_en`, and `short_name_en` of at most 40 characters, for chart labels.
- `definition_en`: what is measured, in whom, over what period. Drop the legacy words "proxy", "%" and the variable names from the names.
- `universe_filter`: a restriction in words, such as "Households connected to the grid"; empty means all units. Use `TBD` where the label does not settle it (H5, H6, H12).
- `numerator`: for shares.
- `higher_is`: `BETTER`, `WORSE` or `NEUTRAL`. Poverty, shocks, outages and biomass cooking are `WORSE`. Access, assets and coverage are `BETTER`. Shares of a population or of a budget are `NEUTRAL`.
- For an indicator whose triage rows carry a `hard_case` that this card does not name (H2, H3, H11, H19 and others), take what the row's `notes` say about the definition or universe into `definition_en` or `notes`, and add nothing else. The verifier checks that the fact is there, not the wording.
- `sdg_indicator`: `7.1.1` for `EN_ELEC_ACCESS`, and others only where the label states one.
- `classification`: `COICOP2018` for `CONS_SH`.
- `related` and `related_note`:
  - `EN_ELEC_ACCESS`, `EN_GRID_CONN` and `EN_GRID_USE` each name the other two, and the note says how they are believed to differ and that the definitions are undocumented (H7);
  - `EN_ASSET_COOKER` and `EN_COOK_CLEAN` name each other (H9);
  - `HE_HH_OWNER` relates to `POP_HH_SH` (H10);
  - `SP_HEALTH_COV_HH` and `SP_HEALTH_COV` name each other (H13).
- `source_vars`: the microdata variable where the label shows it (`activ12m`, `couvmal`, `cuisin`, `superf`); otherwise `TBD`.
- `source_questionnaire` and `program`: `TBD`.
- `notes`: the hard-case ID and its open point, and `LEGACY assumed` where the triage notes say that the weight or statistic was guessed.

## Steps

1. Write `indicators_text.csv` with the columns `code, name_en, short_name_en, definition_en, universe_filter, numerator, higher_is, sdg_indicator, classification, related, related_note, source_questionnaire, source_vars, program, notes`.
2. Write `build_indicators.R` (`--root`, `--out-root`). It derives the mechanical columns, joins the text by `code`, stops unless the code sets are identical, and writes `CL_INDICATOR.csv` sorted by `code`, with the 37 columns of `csv_headers.csv`.
3. Run it and commit everything.

## Acceptance checks

- WP07.A1: the `code` set equals the distinct `INDICATOR` values of the triage's MAP rows, and the row count equals `INDICATOR.CODES` in `expected_counts.csv`.
- WP07.A2: every mechanical column equals the triage value for that indicator.
- WP07.A3: `qualifiers` equals the value rebuilt from the triage and `codes.csv` by the rule above.
- WP07.A4: `checks` equals the value rebuilt by the rule above, and every token is in the vocabulary: `RANGE_0_1`, `RANGE_NONNEG`, `AGG_SUM`, `AGG_BRACKET`, `AGG_NPOP_MEAN`, `SUM_TO_1_OVER:<QUAL_VAR>`, `SUM_TO_1_OVER_BRK`, `EQUALS_NPOP_RATIO`, `MONOTONE_IN:POVLINE`, `NONE`.
- WP07.A5: `theme`, `stat_unit`, `statistic`, `weight` and `unit_measure` are codes of their codelists in `codes.csv`. Every `related` code exists in the file.
- WP07.A6: `short_name_en` has at most 40 characters. Every **R** column is filled. `higher_is` is one of the three values.
- WP07.A7: the header equals `csv_headers.csv`. `status` is `DRAFT` on every row.
- WP07.A8: `--out-root <tempdir>` reproduces the file byte for byte.

## Verifier focus

For 15 indicators chosen at random, read the legacy labels behind the code, and judge whether `definition_en`, `universe_filter` and `higher_is` say what the label says and nothing more. Any invented fact (a recall period, an age range, a source that the label does not show) is a failure.
