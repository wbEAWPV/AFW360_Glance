## Interface (fixed; WP12, WP13 and WP14 build to it at the same time)

- Each module file defines functions named `vc_<module>_<check>(ctx)`.
  - Each returns a tibble with the columns `check_id, severity, file, row_key, message`. Zero rows means pass.
  - `ctx` comes from `build_ctx()`.
  - `check_id` is `<MODULE>.<NAME>`, with your modules `STRUCT`, `CODES` and `META`.
  - `severity` is `ERROR`, `WARN` or `INFO`.
- `Rscript pipeline/validate.R --root . [--metadata-only] [--data <file> ...] --out <findings.csv>`
  - It sources `io.R`, `constants.R`, `codes.R`, `ctx.R`, `plan.R` and every `pipeline/R/validate_*.R` that exists. It must work when the other three packages' modules are absent.
  - It discovers the checks with `ls(pattern = "^vc_")` and runs them in alphabetical order.
  - Without `--data` it validates every `data/AFW360_HH_*.csv` that is not a manifest. With `--metadata-only` it loads no data, and a check that needs data returns zero rows.
  - It writes the findings CSV sorted by `check_id`, `file` and `row_key`, and prints one summary line per severity.
  - Exit codes: 0 when there is no `ERROR`; 1 when there is at least one `ERROR`; 2 when a check crashes. On a crash it writes the findings collected so far, adds a finding `<MODULE>.CRASH` that names the function and the message, and carries on with the remaining checks.

**Findings format** (word for word the same on the cards WP11 to WP14):

- `file` is the path relative to the root, with forward slashes.
- `row_key`:
  - for a data row, the 18 key values joined by one space;
  - for a row of a metadata or content CSV, `<column>=<value>` of the column or columns that identify the row, joined by one space (`code=URB`, or `ref_area=GNB sheet=ZAE column=estimateEst`);
  - for a feature of a GeoPackage, `layer=<layer> geo_code=<code>`;
  - empty for a finding about a whole file.
- The cap: when one check has more than 20 findings for one file, keep the first 20 in `row_key` order, and add one finding with the same `check_id` and severity, an empty `row_key`, and the message `SUMMARY: <n> findings in total, 20 shown`.

## Checks to implement

**STRUCT** (data files)

- `STRUCT.HEADER`: the header equals the DSD's `id` column, in the same names and order.
- `STRUCT.EMPTY_KEY`: no key cell is empty.
- `STRUCT.DUPLICATE_KEY`: the 18-column key is unique.

**CODES** (data files)

- `CODES.UNKNOWN`: every coded cell is in its codelist, or is a sentinel that the DSD allows for that column.
- `CODES.GEO_AREA`: `GEO` is `_T`, or a `CL_GEO` code of the row's `REF_AREA`.
- `CODES.GEO_ADM0`: a geometry-only ADM0 code is never used in `GEO` (gap k). Severity `ERROR`.
- `CODES.BRK_SLOTS`: the breakdown slots are filled from the left; they follow ascending `slot_order`, with ties broken by `var_code`; no variable appears twice; unused slots are `_T`.
- `CODES.QUAL_SLOTS`: the same for the qualifier slots; unused slots are `_Z`.
- `CODES.SEX_AGE_UNIT`: `SEX` and `AGE` are `_Z` exactly when the indicator's `stat_unit` is not `IND`.
- `CODES.BRK_UNIT`: every breakdown variable used lists the indicator's `stat_unit` in its `applies_to_units`.
- `CODES.QUAL_DECLARED`: every qualifier used is allowed by the indicator's `qualifiers` field, or required by a breakdown in the same row (`requires_qual`). The field's grammar is one entry per variable, entries separated by one space, each `VAR:CODE,CODE`, where `VAR:*` allows every category and `_Z` allows none.
- `CODES.VALID_WITH`: a qualifier whose `valid_with` is filled appears only with those categories. `_Z` means that the required variable must be absent. Otherwise `CL_QUAL_VAR.requires` holds.
- `CODES.DRAFT`: a `DRAFT` code used in a data file gives `WARN` when the file's manifest has `status = DRAFT`, and `ERROR` otherwise. Aggregate it to one finding per file and code, not one per row.

**META** (metadata and content files)

- `META.HEADER`: each file listed in `COLUMNS.csv` that exists has exactly those columns, in order.
- `META.REQUIRED`: every **R** column is filled.
- `META.CODE_SYNTAX`: the code column of every `CL_*` file passes the code pattern, and no code starts with `_T` or `_Z`.
- `META.CODE_UNIQUE`: codes are unique within a file. `CL_GEO_SCHEME` is unique on `ref_area` plus `code`.
- `META.REFERENCE`: every one of these references resolves:
  - `var_code`, `parent` and `replaced_by`;
  - `source_id` and `scheme`;
  - `nests_in`, `requires`, `requires_qual` and `valid_with`;
  - `theme`, `stat_unit`, `statistic`, `weight` and `unit_measure` in `CL_INDICATOR`;
  - `INDICATOR`, `MEASURE_QUALS` and `DEFINING_BREAKDOWN` in `SERIES_PLAN`;
  - `series_id` in `LEGACY_LABELS`;
  - the codes in `LEGACY_COLUMNS`.
- `META.TBD`: `TBD` gives `WARN` on a `DRAFT` row, and `ERROR` on any other row.
- `META.SLOT_ORDER_TIE`: a repeated `slot_order` gives `WARN`.

Keep findings few: apply the cap of the findings format.

## Steps

1. Implement `validate.R` and the three modules.
2. Write the tests on a temporary copy of the real metadata: `tmp <- make_temp_root(root)`, then a small data file with `make_data_fixture(tmp, "GNB", series_ids = c("POV_HC.POVLINE_PL420.PPP_2021", "POP_HH_SH.HE_COUNT_0", "CONS_SH.COICOP_CP01"))`. Test the clean fixture, then apply one mutation per test with `edit_csv()` and assert its `check_id`.
3. Run your three modules on the real metadata (`validate.R --metadata-only`). For every `ERROR`, decide whether your check or the metadata is wrong. Fix the check when it is yours. If the metadata is wrong, **do not edit it**: list the file, the row and the rule it breaks under "Questions" in your report.

## Acceptance checks

- WP11.A1: on the clean fixture, `validate.R` exits 0 with 0 `ERROR`.
- WP11.A2: each mutation below gives an `ERROR` with exactly its `check_id`, and exit 1:

  | Mutation | `check_id` |
  |---|---|
  | Two data columns swapped | `STRUCT.HEADER` |
  | One `GEO` cell emptied | `STRUCT.EMPTY_KEY` |
  | A row duplicated | `STRUCT.DUPLICATE_KEY` |
  | `GEO` set to `XX99` | `CODES.UNKNOWN` |
  | `GEO` set to the country's ADM0 code | `CODES.GEO_ADM0` |
  | A breakdown moved to slot 2 with slot 1 left `_T` | `CODES.BRK_SLOTS` |
  | `SEX = _T` on a row of an `HH` indicator | `CODES.SEX_AGE_UNIT` |
  | `MEASURE_QUAL_2` of a `POVLINE_PL420` row set to `PPP_2017` | `CODES.VALID_WITH` |
  | `COICOP_CP01` added to a `POV_HC` row | `CODES.QUAL_DECLARED` |
  | A 33-character code in `CL_THEME` | `META.CODE_SYNTAX` |
  | A `parent` that does not exist, in `CL_URBANISATION` | `META.REFERENCE` |
  | A row of `CL_THEME` set to `ACTIVE` with `definition_en = TBD` | `META.TBD` |

- WP11.A3: a check function that calls `stop()` gives exit 2 and a finding `<MODULE>.CRASH`. The other checks still run.
- WP11.A4: the findings file has exactly the columns `check_id, severity, file, row_key, message`.
- WP11.A5: `validate.R --metadata-only` on the real metadata gives 0 `ERROR` from `STRUCT`, `CODES` and `META`, or every such `ERROR` is listed in the implementer's report as a metadata defect, with the file, the row and the rule.
- WP11.A6: the unit tests pass.
