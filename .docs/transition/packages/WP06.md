# WP06 — Breakdowns and qualifiers

- **Wave:** 2. **Depends on:** wave 1 merged, and gate G1. **Slug:** `breakdowns-qualifiers`. **Acceptance script:** `pipeline/acceptance/wp06_breakdowns-qualifiers.R`.

## Goal

The breakdown variables and qualifier variables, with all their categories, generated from the contract's code list and a text file that you write.

## Read (exactly this)

- `packages/COMMON.md` and this card.
- The rows of `contract/codes.csv` for `CL_BRK_VAR` (13 rows), `CL_COMP_BREAKDOWN` (60), `CL_QUAL_VAR` (6) and `CL_QUALIFIER` (42). Print one codelist at a time, and leave out the columns that are empty for it.
- The header rows of the four output files in `contract/csv_headers.csv`.

## Owned outputs

- `pipeline/bootstrap/build_breakdowns_qualifiers.R` and `pipeline/bootstrap/text/breakdowns_qualifiers_text.csv`
- `metadata/codelists/CL_BRK_VAR.csv`, `CL_COMP_BREAKDOWN.csv`, `CL_QUAL_VAR.csv` and `CL_QUALIFIER.csv`

## Rules you need

- A **breakdown** says who is counted, and its categories are subsets of one population. A **qualifier** says what is measured, and every category covers the same population again.
- The structure comes from the seed and is never retyped: `var_code`, `parent`, `order`, `slot_order`, `describes`, `applies_to_units`, `partition`, `requires`, `valid_with` and `value`.
- Each output file takes only its own structural columns from the seed:

  | File | Seed rows (`codelist`) | Structural columns | Text columns from your text seed |
  |---|---|---|---|
  | `CL_BRK_VAR.csv` | `CL_BRK_VAR` | `describes`, `applies_to_units`, `partition`, `requires` (written as `requires_qual`), `slot_order` | `name_en`, `definition_en`, `notes`, `universe`, `classification`, `owner` |
  | `CL_COMP_BREAKDOWN.csv` | `CL_COMP_BREAKDOWN` | `var_code`, `parent`, `order` | `name_en`, `definition_en`, `notes` |
  | `CL_QUAL_VAR.csv` | `CL_QUAL_VAR` | `slot_order`, `requires` | `name_en`, `definition_en`, `notes`, `owner` |
  | `CL_QUALIFIER.csv` | `CL_QUALIFIER` | `var_code`, `value`, `valid_with`, `order` | `name_en`, `definition_en`, `notes`, `basis` |

  Select the file's columns from `csv_headers.csv` before writing, so that no text column leaks into a file that lacks it.
- `valid_with = _Z` on a poverty line (`POVLINE_NPL`, `POVLINE_NPL_FOOD`) means that the line takes no PPP round. It overrides `CL_QUAL_VAR.requires` for that category (gap n).
- You write only the text: `name_en`, `definition_en`, `notes`, `universe`, `classification`, `basis` and `owner`.
- `definition_en` must give the boundary rule wherever it is not obvious: age cutoffs, ISIC groupings, quantile ranking rules. Where the inputs do not settle it, say so in the definition; do not invent a rule.

**Breakdown variables.** `owner` is "AFW DIP/POV team" on every variable.

| Variable | Universe | Points the text must make |
|---|---|---|
| `QUINT` | All households | Quintiles of consumption per capita. The ranking (national or within-area) and the weighting are an open decision; say "to be confirmed". |
| `DEC_MKT` | All households | Deciles of market income, used for fiscal incidence. Its ranking differs from `QUINT`. |
| `HHH_SEX` | All households | Sex of the household head. |
| `HHH_AGE` | All households | Age of the household head. The cutoff is unconfirmed (H17): the codes say 35, the dashboard's label implies 29 or 30. Say so in `definition_en` and `notes`. |
| `POOR` | All households | Poverty status at the poverty line named in the same row's qualifiers. |
| `HE_COUNT` | All households | Number of non-agricultural household enterprises: 0, 1, 2, 3, and 4 or more. |
| `EMP_STATUS` | Persons aged 15–64 | Employed in the last 12 months, or not. |
| `EMP_SECTOR` | Employed persons aged 15–64 | ISIC Rev.4: `AGR` is section A, `IND` sections B to F, `SER` sections G to U. `classification = ISIC Rev.4`. |
| `EMP_ISIC` | `TBD` (H5: the legacy label says "HH workers") | ISIC Rev.4 sections A to U; use the official section titles. `classification = ISIC Rev.4`. |
| `EMP_TYPE` | Employed persons aged 15–64 (assumed) | Wage and non-wage employment. `classification = ICSE`. |
| `EMP_FORMAL` | `TBD` (H6) | Formal (`Y`) and informal (`N`) employment. |
| `HEO_SEX` | Non-agricultural household enterprises | Sex of the enterprise's main owner. |
| `HEO_MSTAT` | Non-agricultural household enterprises | Whether the main owner is married. |

**Qualifiers.** `owner` is "AFW DIP/POV team" on every variable.

- `WELFARE` is the welfare aggregate the measure is built on: consumption per capita, and the income concepts market, market plus pensions, net market, disposable, consumable and final.
- `POVLINE`: \$2.15, \$3.65 and \$6.85 are the international, lower-middle-income and upper-middle-income lines at 2017 PPP. \$3.00, \$4.20 and \$8.30 are their 2021 PPP replacements.
  - For these six, `basis` is "PPP$ per person per day".
  - For `POVLINE_NPL` and `POVLINE_NPL_FOOD` (the national line and the national food line of the survey), `value` is empty and `basis` is "Local currency; the value is in SURVEYS.csv".
- `PPP` is the PPP round.
- `COICOP` is the COICOP 2018 division, 01 to 13; use the official division titles.
- `ACQ` is how the food was acquired (H2): purchased, own production, gifts, in-kind. `ACQ_GIFT` and `ACQ_INKIND` are registered but not populated by the legacy tables.
- `FI` is the fiscal instrument: direct taxes, direct transfers, indirect taxes, subsidies, in-kind education, in-kind health, and all instruments together.

## Steps

1. Write `breakdowns_qualifiers_text.csv` with the columns `codelist, code, name_en, definition_en, notes, universe, classification, basis, owner`, one row per seed row (121 rows). Generate the repetitive rows (ISIC sections, COICOP divisions, deciles, quintiles) with a few lines of R; do not type them.
2. Write `build_breakdowns_qualifiers.R` (`--root`, `--out-root`). It:
   - reads the seed and the text file;
   - stops unless the two hold exactly the same (codelist, code) pairs;
   - writes the four files with the columns of `csv_headers.csv`, their rows in the seed's order, `status = DRAFT` and `version_added = 0.1.0`.
3. Run it and commit everything.

## Acceptance checks

- WP06.A1: for each of the four files, the code set equals the seed's, and `var_code`, `parent`, `order`, `slot_order`, `describes`, `applies_to_units`, `partition`, `requires` or `requires_qual`, `valid_with` and `value` equal the seed's. Compare `value` and `slot_order` as numbers.
- WP06.A2: every category's `var_code` exists in its variable file, and the category code starts with `<var_code>_`.
- WP06.A3: `slot_order` is unique within `CL_BRK_VAR` and within `CL_QUAL_VAR`.
- WP06.A4: every `requires`, `requires_qual`, `valid_with` (other than `_Z`) and `parent` value resolves to a code of the right file.
- WP06.A5: every `applies_to_units` value is one of `IND`, `HH`, `HE`, `PLOT`.
- WP06.A6: every code has at most 32 characters and passes the code pattern.
- WP06.A7: the headers equal `csv_headers.csv`. Every **R** column is filled. `TBD` appears only in `universe`.
- WP06.A8: the six international poverty lines carry `value` 2.15, 3.65, 6.85 (with `PPP_2017`) and 3.00, 4.20, 8.30 (with `PPP_2021`). `POVLINE_PL300` is valid with `PPP_2021` only.
- WP06.A9: `--out-root <tempdir>` reproduces the four files byte for byte.
