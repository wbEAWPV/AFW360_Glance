# WP04 — Small codelists and `CL_AREA`

- **Wave:** 2. **Depends on:** wave 1 merged, and gate G1. **Slug:** `small-codelists`. **Acceptance script:** `pipeline/acceptance/wp04_small-codelists.R`.

## Goal

The ten small codelists that every other file refers to. A short R script generates them from the contract's code list and a text file that you write.

## Read (exactly this)

- `packages/COMMON.md` and this card.
- The rows of `contract/codes.csv` for the ten codelists below (55 rows). Print `codelist`, `code`, `parent` and `order`, filtered with R.
- The header rows of `CL_URBANISATION.csv`, `CL_STATISTIC.csv` and `CL_AREA.csv` in `contract/csv_headers.csv`. The other seven files have only the seven common columns.

## Owned outputs

- `pipeline/bootstrap/build_small_codelists.R`
- `pipeline/bootstrap/text/small_codelists_text.csv`
- `metadata/codelists/CL_SEX.csv`, `CL_AGE.csv`, `CL_URBANISATION.csv`, `CL_OBS_STATUS.csv`, `CL_THEME.csv`, `CL_UNIT.csv`, `CL_STAT_UNIT.csv`, `CL_STATISTIC.csv`, `CL_WEIGHT.csv` and `CL_AREA.csv`

## What the codes mean

Use these meanings for `name_en` and `definition_en`. They come from the data standard.

| Codelist | Meaning |
|---|---|
| `CL_SEX` | `F` female, `M` male: the sex of the individual counted, never of the household head |
| `CL_AGE` | Age bands of the individual counted: `Y_LT15` under 15, `Y15T24` 15 to 24, `Y25T64` 25 to 64, `Y_GE65` 65 and over |
| `CL_URBANISATION` | `U` urban, `R` rural, `CAP` capital city (`parent = U`), `OU` other urban (`parent = U`) |
| `CL_OBS_STATUS` | `A` normal value. `E` model-based: projection, nowcast or microsimulation. `O` no value available; the value is empty (widened by decision D9; put in the code's `notes`, not in `definition_en`, that a legacy conversion marks such a row with an `OBS_COMMENT` that starts with `LEGACY_EMPTY:`). `M` cannot exist: the cell is outside the indicator's universe by definition; the value is empty. |
| `CL_THEME` | `POV` poverty, `INEQ` inequality, `FISC` fiscal incidence, `POP` population, `CONS` consumption, `JOB` jobs, `HE` household enterprises, `AGR` agriculture, `EN` energy, `HOUS` housing, `SHK` shocks, `SP` social protection |
| `CL_STAT_UNIT` | What is counted: `IND` individuals, `HH` households, `HE` non-agricultural household enterprises, `PLOT` agricultural plots |
| `CL_STATISTIC` | `PROPORTION`, `MEAN`, `MEDIAN`, `TOTAL`, `RATIO_TOTALS` (ratio of two weighted totals), `GINI`, `INDEX`. `admits_se` is `Y` for all except `INDEX`, which is `N`. |
| `CL_WEIGHT` | `POP` household weight times household size, for person-level statistics computed on household data; `HH` household weight; `IND` individual weight; `HE` enterprise weight |
| `CL_UNIT` | `SHARE` 0 to 1, never 0 to 100; `INDEX` for Gini and similar; `PERSON`; `HH`; `HE`; `LCU` local currency units; `PPP_USD`; `HA` hectares; `TLU` tropical livestock units; `DAY`; `YEAR`; `COUNT` |
| `CL_AREA` | `SEN` Senegal (`iso2 SN`, `currency XOF`, `wb_region AFW`) and `GNB` Guinea-Bissau (`GW`, `XOF`, `AFW`). Both use `XOF`, the CFA franc BCEAO, never `XAF`. |

## Steps

1. Write `pipeline/bootstrap/text/small_codelists_text.csv` with the columns `codelist, code, name_en, definition_en, notes, admits_se, iso2, currency, wb_region`, one row per code (55 rows).
   - Give every code a real `name_en` and `definition_en` from the table above.
   - The last four columns are filled only for the codelist that has them.
2. Write `pipeline/bootstrap/build_small_codelists.R` (`--root`, `--out-root`). It:
   - reads `contract/codes.csv` and the text file;
   - stops if the two do not hold exactly the same (codelist, code) pairs;
   - writes each of the ten files, with its columns from `contract/csv_headers.csv`, its rows in the seed's `order`, `status = DRAFT`, `version_added = 0.1.0`, `replaced_by` empty, and `parent` taken from the seed.
3. Run it, and commit the script, the text file and the ten outputs.

## Acceptance checks

- WP04.A1: for each of the ten codelists, the set of `code` values equals the set in `contract/codes.csv`.
- WP04.A2: each file's header equals its rows in `csv_headers.csv`, in order.
- WP04.A3: every code passes `^[A-Z][A-Z0-9_]{0,31}$` and does not start with `_T` or `_Z`.
- WP04.A4: `name_en`, `definition_en`, `status` and `version_added` are filled on every row. `status` is `DRAFT` and `version_added` is `0.1.0` everywhere. No `definition_en` is `TBD`.
- WP04.A5: every `parent` in `CL_URBANISATION` is a code of that file. `CAP` and `OU` have parent `U`.
- WP04.A6: `CL_AREA` has the `iso2`, `currency` and `wb_region` values given above. `CL_STATISTIC.admits_se` is `Y` or `N` on every row.
- WP04.A7: the committed blobs (`git cat-file blob HEAD:<path>`) have no BOM and no CR byte.
- WP04.A8: running the script with `--out-root <tempdir>` writes ten files that are byte-identical to the committed ones.

## Verifier focus

Check the definition of each `CL_OBS_STATUS` code and of `POP` in `CL_WEIGHT` against the table above. A wrong meaning here misleads every producer.
