Step 2: Establish an SDMX Data Structure Definition (DSD) for our indicators

The schema every number in the data files follows

Author

Eduard Bukin

Published

October 2, 2026

The file sdmx/structures/AFW360_structures.xml is an SDMX-ML 3.1 structure message. It is generated by pipeline/build_sdmx.R from metadata/, so you never edit it by hand. Its core is the Data Structure Definition (DSD) WB.AFW360:DSD_AFW360_HH(0.3.0). Everything else in the file either feeds the DSD or points at it.

What a DSD does

A DSD is the schema for every number in data/*.csv. It says three things:

  1. Which columns identify an observation (the dimensions, together called the “key”).
  2. Which columns hold numbers (the measures).
  3. Which columns describe a number without identifying it (the attributes).

It also ties each column to a concept (its meaning, in CS_AFW360) and to a representation: either a codelist of allowed values or a plain type such as Double or String. That is why every country file has the same 37 columns, with the same codes in them.

1. Dimensions: the 19-column key

Every combination of these 19 values must be unique in a dataset.

Group Dimension Codelist What it says
Context FREQ CL_FREQ (only A, annual) how often
REF_AREA CL_AREA (SEN, GNB) country, ISO3
GEO CL_GEO (36 codes, e.g. SN01) subnational area, or _T for the whole country
ESTIMATION CL_ESTIMATION SURVEY or MODEL
What INDICATOR CL_INDICATOR (62 codes) e.g. POV_HC, AGR_CULTIVATES
Who (fixed breakdowns) SEX, AGE, URBANISATION CL_SEX, CL_AGE, CL_URBANISATION standard SDMX breakdowns
Who (flexible breakdowns) COMP_BREAKDOWN_1…5 CL_COMP_BREAKDOWN (61 codes) e.g. QUINT_Q1, DEC_MKT_D03; _T if unused
How it is measured MEASURE_QUAL_1…5 CL_QUALIFIER (43 codes) welfare aggregate, poverty line, PPP round, etc.; _Z if unused
When TIME_PERIOD (time dimension) GregorianYear a 4-digit year

The main design choice is the two groups of five “slot” dimensions:

  • COMP_BREAKDOWN_n splits the population: by quintile, decile, sex or age of the household head, poverty status, employment sector, and so on.
  • MEASURE_QUAL_n changes the definition of the indicator: which poverty line, which PPP round, which welfare concept.

Slots are filled left to right in a fixed slot_order. This keeps the key the same width for every indicator: adding a new kind of breakdown or qualifier means adding codes to a codelist, not changing the DSD.

The two “nothing” codes mean different things:

  • _T means “total”, i.e. not broken down.
  • _Z means “not applicable”. For example, SEX=_Z on a household-level indicator.

2. Measures: the numbers (9)

The DSD uses SDMX 3.x multiple measures, so one row can carry a value and its precision statistics:

  • OBS_VALUE is mandatory. It is unrounded and in base units, so rates are shares between 0 and 1. It is NaN when OBS_STATUS is O or M.
  • The other eight are optional (minValue="0" where a negative value makes no sense):
    • STD_ERR, CI_LOWER, CI_UPPER: sampling error and the 95% confidence interval.
    • N_OBS, N_POP, N_OBS_NUM: unweighted records, weighted population, and numerator records for shares.
    • DEFF, DF: design effect and degrees of freedom.

They are optional in the DSD, but the project validator requires them on PRODUCER-source rows. Today’s rows all come from converting the legacy workbooks, so these columns are empty.

3. Attributes: describe a number, don’t identify it (6)

Attribute Usage Attached to Representation
SERIES_ID mandatory INDICATOR + the 10 slot dimensions String, e.g. POV_HC.POVLINE_PL300.PPP_2021
UNIT_MEASURE mandatory REF_AREA + INDICATOR CL_UNIT_MEASURE (SHARE, LCU, PPP_USD, HA…)
OBS_STATUS mandatory observation, linked to OBS_VALUE CL_OBS_STATUS (A, E, O, M…)
SOURCE_ID mandatory observation CL_SOURCE (the program run that produced the row)
PRECISION optional observation Double, the rounding unit (e.g. 0.01 for legacy values)
OBS_COMMENT optional observation free text

What each AttributeRelationship means:

  • SERIES_ID depends only on the “what and how” dimensions, not on country, area or year. It is the readable series name the dashboard matches on. It is a plain string, not a codelist, because SDMX IDs cannot contain dots.
  • UNIT_MEASURE depends on the country as well as the indicator, because local currency (LCU) resolves to that country’s ISO 4217 code.
  • OBS_STATUS has a MeasureRelationship to OBS_VALUE: the status describes the main value, not the standard error.

A real row, read through the DSD

From data/AFW360_HH_SEN_2021_SURVEY.csv:

dataflow, WB.AFW360:AFW360_HH(0.3.0), R,
A, SEN, SN01, SURVEY, POV_HC, _T,_T,_T, _T,_T,_T,_T,_T, POVLINE_PL420,PPP_2021,_Z,_Z,_Z, 2021,   ← key
0.03, ,,,,,,,,                                                                                      ← measures
POV_HC.POVLINE_PL420.PPP_2021, SHARE, 0.01, A, SEN_EHCVM2021_LEGACY_v1,                           ← attributes

Read through the DSD: in Senegal, region SN01, the survey-based poverty headcount at the $4.20 line, 2021 PPP, for the whole population (no breakdowns) in 2021, is 0.03 (3%). It is a share, rounded to 0.01, the status is normal (A), and it was produced by the legacy EHCVM 2021 conversion.

The first three columns are SDMX-CSV 2.1 bookkeeping:

  • STRUCTURE=dataflow says the next column names a dataflow.
  • STRUCTURE_ID names the dataflow AFW360_HH, which points to this DSD.
  • ACTION=R means “replace”.

How the DSD connects to the rest of the file

AgencyScheme (WB → AFW360)
   └─ ConceptScheme CS_AFW360 ──┐  meaning of each column
   └─ 22 Codelists ─────────────┤  allowed values
                                ▼
            DataStructure DSD_AFW360_HH        ← the schema
                                ▲
            Dataflow AFW360_HH ─┘              ← "this dataset uses that DSD" (named in every CSV row)
                                ▲
            ProvisionAgreement PA_AFW360_HH    ← data provider AFW_POV supplies that dataflow

The file also has a separate Metadata Structure (MSD) and Metadataflow. They describe the reference metadata for surveys, sources, text and figures (sdmx/metadata/MDS_*.csv), not the observations. That is also why some codelists, such as CL_SURVEY, CL_THEME, CL_STATISTIC and CL_FIGURE, are not used by any DSD dimension.

Caveats

  • Every artefact is version 0.3.0 and the codes are still DRAFT. WB.AFW360 is a local placeholder agency until the structures are registered with the World Bank.
  • Fusion Metadata Registry 12.4.2 rejects SDMX-ML 3.1, so this DSD is loaded into FMR with --sdmx-ml-version 3.0. The DSD loads, but the MSD, the metadataflow and the metadata provision agreement are left out, so the metadata files are not checked in FMR.
  • To change the DSD, edit metadata/structure/DSD_AFW360_HH.csv (named in the AFW_SOURCE_FILE annotation) and regenerate the XML with build_sdmx.R.
